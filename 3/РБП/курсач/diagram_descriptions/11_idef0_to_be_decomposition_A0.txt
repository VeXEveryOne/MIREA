Название диаграммы
IDEF0 to-be. Декомпозиция A0.

Где вставляется в отчете
Раздел 4.1, рисунок 4.2.

Назначение
Показать, как пять подпроцессов A1-A5 сохраняются после реинжиниринга, но внутри них появляются автоматизированные проверки CMS.

Элементы
Блоки:
A1 «Принятие и первичная проверка заказа с автоматическими контрольными признаками».
A2 «Подготовка задания и обязательная фиксация комплектующих/SN».
A3 «Информационное сопровождение сборочного этапа со статусным контролем».
A4 «Фиксация результатов диагностики с автоматическим контролем заполненности».
A5 «Финальный контроль полноты и передача сведений о готовности».

Входы слева:
1. Карточка заказа -> A1.
2. Спецификация конфигурации -> A1.
3. Учетные данные склада -> A2.
4. Данные диагностических утилит -> A4.

Управления сверху:
1. Регламент обработки заказа -> A1-A5.
2. Правила автоматической проверки цены/состава/статуса -> A1.
3. Правила обязательности SN -> A2.
4. Правила смены статусов -> A1, A3, A5.
5. Правила обработки диагностических замечаний -> A4.
6. Правила финального контроля полноты карточки -> A5.

Механизмы снизу:
1. Внутренняя CMS -> A1-A5.
2. Руководитель отдела производства -> A1, A5.
3. Платформер -> A2, A3.
4. Сборщик ПК -> A3.
5. Инженер тестирования -> A4.
6. Упаковщик -> A5.

Выходы справа:
1. Проверенная карточка заказа.
2. Подтвержденные SN.
3. Структурированный результат диагностики.
4. Отметка о готовности.
5. Сведения, переданные в следующий процесс.

Связи / порядок соединения
1. Расположить A1-A5 слева направо.
2. A1 -> A2: «Контрольные признаки заказа сформированы; исключения проверены».
3. A2 -> A3: «Задание сформировано; SN заполнены в обязательной форме».
4. A3 -> A4: «Статус передачи на диагностику зафиксирован».
5. A4 -> A5: «Диагностика пройдена; замечаний нет».
6. A4 -> A2 или A3 обратной стрелкой: «Передача дальше заблокирована; требуется уточнение/устранение причины».
7. A5 -> внешний выход: «Карточка прошла контроль полноты; сведения переданы дальше».

Развилки и исключения
1. A1: если CMS выявила исключения по цене/составу/статусу, заказ не принимается в работу до уточнения.
2. A2: если SN не заполнены, переход дальше блокируется.
3. A4: если есть замечания диагностики, переход к A5 блокируется.
4. A5: если карточка неполная, сведения не передаются в следующий процесс.

Что выделить цветом или пометкой
Выделить цветом все изменения:
- автоматическая проверка цены/состава/статуса;
- обязательная форма SN;
- автоматический контроль результата диагностики;
- блокировка передачи дальше;
- финальный контроль полноты карточки.

Проверка перед вставкой в отчет
1. Есть те же A1-A5, что и в as-is.
2. Новые автоматизированные элементы явно выделены.
3. CMS подключена к каждому подпроцессу.
4. В диаграмме есть блокировка при замечаниях.
