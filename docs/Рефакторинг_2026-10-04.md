# Рефакторинг MIREA — 04.10.2026

Очистка касается структуры, повторяющихся материалов и инструментов сборки. Учебные задания разных лет не объединялись по одному лишь сходству кода. Готовые DOCX/PDF РОП и ИМ сохранены побайтно; их SHA-256 сверены со снимком до очистки.

Рабочая папка сократилась примерно с 8,14 до 5,78 ГБ, то есть на 2,36 ГБ. Аудит не учитывает `.git`, содержимое двух подмодулей и каталогов-ссылок. Из индекса убраны 28 506 временных файлов. Число групп точных дубликатов уменьшилось с 297 до 30; оставшиеся совпадения сохраняют отдельное назначение. Битых локальных ссылок Markdown нет.

## Что изменено

- Убраны временные сборки, кэши, блокировки Office, скомпилированные программы с сохранившимися исходниками и подтверждённые лишние копии документов. Из Git исключены ранее добавленные зависимости и результаты промежуточных проверок.
- Для РОП оставлен один комплект практик 1–8: отчёт DOCX/PDF, восемь презентаций, 12 актуальных моделей и экспорт 38 рисунков. Модели находятся в `Модели/`, рисунки — в `Экспорт/PNG/`, генераторы — в `Исходники/`. Версионные папки и параллельные копии `_готово` убраны.
- Исправлены реестры, ссылки и пути сборки после перемещений. У генераторов РОП, ИМ и KNIME убраны привязки к старым временным каталогам; подключение внешних библиотек вынесено в `tools/runtime.mjs`.
- Генератор второй практики БД использует общий форматировщик, не перезаписывает исходный черновик и позволяет собирать результат в отдельный каталог. Зависимости сборки описаны отдельно от окружения Jupyter.
- Для двух проектов Playlist Maker добавлена `.gitmodules`. Их разные коммиты и собственные истории сохранены. Завершённые локальные Git-упражнения представлены обычными файлами; их вложенные истории перенесены в резервную копию.
- Добавлены навигационные README, общий аудит репозитория и инструмент безопасного перемещения явно выбранных файлов в резервную папку. Правила структуры закреплены в `AGENTS.md` и `.gitignore`.
- Для проверенного комплекта РОП отключена автоматическая замена переводов строк в Git: манифест SHA-256 проверяет точные байты, поэтому клонирование не должно менять их. Перед коммитом хэши сверяются также с файлами в индексе Git.

## Что намеренно сохранено

PDF рядом с DOCX, исходники рядом с готовой работой и иллюстрации для отчёта не являются лишними копиями. Одинаковые наборы данных независимых практик, Gradle Wrapper и одинаковые решения отдельных заданий сохранены. Виртуальное окружение БД не включается в Git, но оставлено для локальной работы. Ранее исключённые большие видео не удалялись.

## Резервная копия и восстановление

Убранные материалы не уничтожены: они перенесены за пределы репозитория в `D:/GitHub/MIREA_cleanup_backup_2026-10-04/`. В `removed/` сохранена исходная структура путей, в `before_edits/` — снимки изменённых источников. `moved_files.json` связывает исходные и резервные пути. Для выборочного восстановления скопировать нужный файл обратно, предварительно проверив, что он не перезапишет новую версию.

Полная инвентаризация до и после находится в `audit_before.json` и `audit_after.json` резервной папки. Снимок Git-индекса хранится только для аварийного восстановления и не должен автоматически заменять текущий индекс. По запросу пользователя результат фиксируется отдельным коммитом и отправляется в `origin/main`; резервная папка в Git не включается.

## Дальнейшая работа

Новые материалы сохранять внутри дисциплины и курса. Один актуальный результат хранить под каноническим именем; промежуточные проверки выполнять в `.cache/`. После перемещений обновлять ссылки и манифесты. Для контрольного аудита из корня репозитория:

```powershell
python tools/repository_audit.py --hash --output .cache/repository_audit.json
```

Аудит только читает файлы: совпадение SHA-256 не является автоматическим разрешением на удаление.
