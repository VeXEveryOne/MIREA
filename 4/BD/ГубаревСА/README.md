## Ноутбуки и фактические результаты

- [№1 — личный выполненный Notebook](Ноутбуки/ТИАБД_ПР1_ГубаревСА.ipynb): 31 кодовая ячейка, восемь графиков, самостоятельный Bike Sharing, экспорт и повторное чтение. [Результаты](Результаты/ПР1).
- [№2 — личный выполненный Notebook](Ноутбуки/ТИАБД_ПР2_Визуализация_ГубаревСА.ipynb): 11 кодовых ячеек, шесть рисунков, три настройки каждого алгоритма, измерения времени и trustworthiness. [Результаты](Результаты/Визуализация).
- [№3 — выполненный Notebook курса](../spark_lab/Practice_3.ipynb): девять кодовых ячеек; [JSON результатов](../spark_lab/results/pr3.json), [выгрузки](../spark_lab/exports).
- [№4 — выполненный Notebook курса](../spark_lab/Practice_4.ipynb): 12 кодовых ячеек; [JSON результатов](../spark_lab/results/pr4.json), [физические планы](../spark_lab/results/plans), [настоящие скриншоты](../spark_lab/screenshots).
- [Исходники системы хранения](Исходники/ПР2_Хранение): схема БД, импорт, аналитические SQL, Docker Compose, настройки мониторинга и дашборд.

Первый и второй личные notebooks повторно выполнены в чистых ядрах 5 октября 2026 года. Они читают неизменённые общие исходные CSV и записывают свои результаты в этот каталог. Отчёты №3–4 и отчёт по системе хранения подготовлены на основе проверенных сохранённых запусков общего учебного стенда; их измерения и снимки не выдаются за новый запуск. Исходные отчёты другого студента сохранены без изменения.

Учебный стенд хранения использует официальный PostgreSQL 16 и community-бандл ADCM; это учебная модель ADPG, а не промышленная сборка Arenadata PostgreSQL. В №3 SQLite восстановлена из предоставленных CSV Olist: фактические строки и расхождение количества отзывов с примером методички отражены в отчёте и манифесте. В №4 выбран вариант B, который методичка разрешает выбрать самостоятельно.

Визуализация использует исходные коды сезона, чтобы избежать противоречивой расшифровки в разных метаданных. Температура и ветер сохраняются в нормированной шкале. Времена t-SNE и UMAP относятся к текущему сохранённому запуску; первый UMAP включает JIT-компиляцию.

## Повторное выполнение и сборка

Из каталога `4/BD`:

```powershell
.\.venv\Scripts\python.exe ГубаревСА\Исходники\execute_notebooks.py
```

Повторное выполнение меняет результаты личных notebooks, включая времена. После него пересобрать отчёты:

```powershell
python ГубаревСА\Исходники\build_reports.py
```

Для сборки нужны `pandas`, `python-docx` и Pillow. В текущей сессии использована комплектная среда Codex. Последующий экспорт выполняется [export_reports.ps1](Исходники/export_reports.ps1) через отдельный невидимый экземпляр Word; он обновляет содержание, номера страниц и создаёт PDF из текущего DOCX. После пересборки просмотреть весь PDF.

Для Spark: инструкции среды, подготовки SQLite/КОМУС и Run All находятся в [spark_lab/README.md](../spark_lab/README.md). Сырые данные Spark хранятся локально в учебной VM и не включены в Git. Старые скриншоты не следует использовать как подтверждение нового запуска.

Титульные листы основаны только на первой странице ИСУРО; основная часть соответствует [единому справочнику](../../../Оформление_отчётов.md). Содержание создано полями Word и обновлено при экспорте. Все таблицы без заливки. Временные сборки и изображения проверки сохранены в корневом `.cache/`.
