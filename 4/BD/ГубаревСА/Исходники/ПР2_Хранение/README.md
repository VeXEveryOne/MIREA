# Учебный стенд системы хранения

Конфигурация сохранена из ранее выполненной практики: PostgreSQL 16, ADCM 2.12.0, postgres_exporter, Prometheus и Grafana. Community-бандл ADCM проверяет учебные сервисы; бинарная промышленная сборка ADPG здесь не используется.

1. В Ubuntu с установленными Docker Engine и Compose скопировать этот каталог в рабочий каталог стенда.
2. Скопировать `.env.example` в `.env` и заполнить три пароля. Локальный `.env` исключён из Git.
3. Подготовить 11 CSV Olist, включая две маркетинговые таблицы. `prepare_data.py` переводит стандартные имена файлов в ожидаемые имена без изменения строк. Сырые данные находятся в локальном `data/`, исключённом из Git.
4. Выполнить `docker compose up -d`. В текущей конфигурации ADCM доступен на 8000, PostgreSQL на 5432, Prometheus на 9090, Grafana на 11210.
5. В пустой базе выполнить схему и импорт:

```bash
docker compose exec -T adpg psql -U postgres -d ecommerce -f /sql/schema.sql
docker compose exec -T adpg psql -U postgres -d ecommerce -f /sql/load.sql
docker compose exec -T adpg psql -U postgres -d ecommerce -f /sql/analytics.sql
```

Импорт добавляет недостающие категории в словарь перевода и нормализует неизвестные ссылки продавцов в `leads_closed`. Исходные CSV остаются неизменными. Схема и ключи создаются до импорта; скрипт останавливается при первой SQL-ошибке.

Grafana получает PostgreSQL datasource и дашборд из provisioning. Содержимое дашборда соответствует четырём аналитическим задачам отчёта и двум дополнительным панелям. Бандл ADCM можно упаковать командой `tar -czf adpg-ecommerce-lab.tar.gz -C adcm_bundle .` и загрузить через Bundles. Действия бандла проверяют доступность уже развёрнутых сервисов.

Имеющиеся скриншоты отчёта относятся к сохранённому запуску исходного учебного стенда. При новом запуске версии образов с тегом `latest`, время и экранные снимки могут измениться.
