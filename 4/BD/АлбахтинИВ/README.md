## Выполнение и исходники

[execution.json](Результаты/execution.json) фиксирует полный успешный запуск
четырёх ноутбуков: 31 + 11 + 9 + 12 = 63 ячейки кода, ошибок 0.
В каждом ноутбуке сохранены результаты именно новой VM.

- [ПР1](Ноутбуки/ТИАБД_ПР1_АлбахтинИВ.ipynb) и [визуализация](Ноутбуки/ТИАБД_ПР2_Визуализация_АлбахтинИВ.ipynb).
- [Spark №3](Spark/Practice_3.ipynb) и [Spark №4](Spark/Practice_4.ipynb).
- [Результаты №3](Spark/results/pr3.json), [№4](Spark/results/pr4.json), [хранения](Результаты/Хранение/storage.json), [действий ADCM](Результаты/Хранение/adcm.json).
- `Результаты/`: свежие графики, таблицы, статические и интерактивные визуализации.
- `Spark/results/plans/`, `Spark/exports/`: фактические планы, снимки REST API и агрегаты CSV/Parquet.
- `Spark/screenshots/`, `Результаты/Хранение/`: реальные снимки Spark UI, ADCM, Grafana и framebuffer VirtualBox.
- [Зависимости VM](Исходники/requirements-vm.txt), [подготовка](Исходники/setup_vm.sh), [полный запуск](Исходники/execute_all.py).
- [Стенд хранения](Исходники/ПР2_Хранение/README.md): схема, импорт, четыре SQL-задачи, Docker Compose, provisioning и community-бандл ADCM.
- [Сборка трёх отчётов](Исходники/build_reports.py) и [сборка хранения/Spark](Исходники/build_extra_reports.py).

Исходные 11 CSV Olist сверяются по [хэшам](Исходники/source_inputs.json).
SQLite восстановлена из исходных CSV с 71 записью перевода категорий; в PostgreSQL
добавлены две отсутствующие категории с NULL-переводом. CSV не редактировались.
КОМУС обрабатывается из предоставленного архива; в Git сохранены агрегаты,
исходный архив и staging остаются в VM. Происхождение описано в [манифесте](Spark/source_manifest.json).

Повторить расчёты в VM:

```bash
cd /home/albakhtin/tiabd
MPLBACKEND=Agg BROWSER_PATH=/usr/bin/google-chrome .venv/bin/python execute_all.py
```

При обычном повторе не задавать `TIABD_CAPTURE=1`: эта опция ставит ноутбуки
на паузу для сохранения живого Spark UI. Для работы в интерфейсе открыть JupyterLab,
ввести локальный токен из `Доступ.txt` и выбрать ноутбук в каталоге `АлбахтинИВ`.

Для пересборки DOCX на Windows установить зависимости документов и выполнить
`Исходники/build_reports.py`, затем `Исходники/build_extra_reports.py` из этого
каталога. После сборки обновить оглавления в Word, экспортировать PDF и проверить
все страницы. Временные рендеры хранить в `.cache/`.

Методичка Spark рекомендует Python 3.11; здесь используется совместимый Python
3.10.12, Spark 3.5.7 и OpenJDK 17. Работа `local[*]` использует два ядра одного узла.
Стенд хранения использует официальный PostgreSQL 16 и учебный community-бандл ADCM;
промышленный дистрибутив Arenadata PostgreSQL не установлен. Эти отличия отмечены
в отчётах. [Паспорт VM и проверка автозапуска](VM.json) содержит фактические версии и UUID.

[Итоговая проверка](Проверка.json): шесть отчётов, 101 страница, 102 контрольных
вопроса, 63 выполненные ячейки без ошибок. Проверены титулы, оглавления, PDF,
каждая конечная страница и контрольные суммы комплекта Губарева.
