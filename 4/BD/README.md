## Ранее сохранённые локальные задания

Каталоги `practice_1` и `practice_2` содержат исходные задания по анализу
данных. Канонические отчёты в них обновлены по новому запуску личной VM Албахтина;
личные результаты и сборка описаны в его комплекте выше.

Каталог разделён по работам:

- [Практическая работа №1](practice_1/README.md) — Pandas, NumPy, EDA и форматы хранения.
- [Практическая работа №2](practice_2/README.md) — Matplotlib, Plotly, t-SNE и UMAP.

Подробные ответы на контрольные вопросы лекций в формате практик:

- [Лекция №1](practice_1/Лекция_1_Контрольные_вопросы.md) — Big Data, архитектуры, масштабирование, ETL/ELT; 8 вопросов.
- [Лекция №2](practice_2/Лекция_2_Контрольные_вопросы.md) — SQL, оконные функции, планы запросов и NoSQL; 8 вопросов.

Общее Python-окружение находится в `.venv`, зависимости перечислены в
`requirements.in` и `requirements.txt`. Команда `run_all.cmd` повторно выполняет
ноутбуки обеих работ, а `start_jupyter.cmd` запускает Jupyter из корня каталога.
Для генерации и проверки DOCX дополнительно установить `requirements-reports.txt`
в используемое Python-окружение; эти библиотеки также доступны в комплектной среде Codex.

## Запуск в VS Code

Откройте в VS Code именно каталог `D:\GitHub\MIREA\4\BD`. Проект уже настроен
на интерпретатор `.venv\Scripts\python.exe`. Для ноутбука выберите ядро
`Python (BD - VS Code)`. Полную пересборку второй работы можно запустить через
`Terminal → Run Build Task` или сочетанием `Ctrl+Shift+B`.

Итоговые DOCX и PDF находятся внутри соответствующих папок `practice_1` и
`practice_2`. Исходное задание второй работы сохранено в `practice_2/assignment`.

## Оформление отчётов

Обе практики оформлены по [единому справочнику](../../Оформление_отчётов.md).
Титульные листы используют макет первой практики ИСУРО; дисциплина —
«Анализ больших данных», преподаватель — Воронцов Ю.А., студент —
Албахтин И.В., группа — ИНБО-12-23.

`practice_2/scripts/build_report.py` использует общий форматировщик из
`tools/report_formatting/bd/`: титульный лист ИСУРО, единые шрифты, интервалы,
подписи и таблицы без заливки. Первая практика служит исходником стилей и
проверяется на неизменность в ходе сборки; старый фиксированный хэш больше не
блокирует запуск. Пробный результат можно направить в отдельный файл переменной
`BD_REPORT_OUTPUT`. После сборки DOCX обновить поля в Word, экспортировать PDF и
проверить все страницы. Запуск ноутбуков от оформления DOCX не зависит.

[Презентация KNIME и её исходники](KNIME/README.md) находятся внутри предмета.
