## Модели и смысловые границы

IDEF0 строится из общего словаря потоков в `build_idef0.mjs`. Проверка определяет стороны подключений по координатам, сравнивает фактические интерфейсы A-0/A0 и родительского A2 с детализацией. SVG редактируемы; PNG предназначены для Word. Не следует независимо менять подписи трёх экспортированных рисунков.

[Модель анализа](Схемы/ПР3_Модель_анализа.omni) содержит пять UML-листов. Для печати последовательности разделены на части с повторёнными участниками; сообщения и условия берутся из общей модели. [Описание файлов практики 3](Схемы/ПР3_О_файлах.md) поясняет различие полной модели и печатной компоновки.

Классы и деятельность практики 4 редактируются в OmniNotation. Для состояний используется отдельный SVG-генератор `build_states.mjs`; это не заявляется как поддержка диаграмм состояний редактором. [Переходы](Схемы/ПР4_Переходы.json) служат одновременно источником таблицы отчёта и проверяемым перечнем переходов.

Внешний обмен различает принятую задачу, подтверждённую публикацию, отказ, временную ошибку и неизвестный исход. UNKNOWN требует сверки; повтор допустим только для подтверждённого непринятия операции, с задержкой и лимитом. Внутренние статусы не объявляются именами полей внешнего API. Внутренние роли и связи с поставщиками являются явно указанными проектными предположениями.

## Сборка и проверка

Команды запускать из корня MIREA с комплектными Node/Python и зависимостями, описанными в [tools](../../tools/README.md). Для TypeScript используется установленный `tsx` из OmniNotation, путь задаётся через `OMNINOTATION_ROOT`. В примере `node` и `python` обозначают эти среды, не случайные глобальные установки.

```powershell
$env:OMNINOTATION_ROOT = 'D:/OmniNotation'
$taskPpoisBuild = Join-Path $PWD ('.cache/ppois/' + [guid]::NewGuid().ToString('N'))
$env:PPOIS_MODEL_OUTPUT = "$taskPpoisBuild/models"
node "$env:OMNINOTATION_ROOT/node_modules/tsx/dist/cli.mjs" 4/ППОИС/Исходники/build_design.mts
node 4/ППОИС/Исходники/build_idef0.mjs
node "$env:OMNINOTATION_ROOT/node_modules/tsx/dist/cli.mjs" 4/ППОИС/Исходники/build_analysis.mts
node 4/ППОИС/Исходники/build_states.mjs
node "$env:OMNINOTATION_ROOT/scripts/export.mjs" "$env:PPOIS_MODEL_OUTPUT/ПР4_Экспорт.json"
python 4/ППОИС/Исходники/revise_reports.py --baseline 4/ППОИС --figures $env:PPOIS_MODEL_OUTPUT --output "$taskPpoisBuild/reports" --working "$taskPpoisBuild/build"
./tools/export_coursework_word.ps1 -Documents (Get-ChildItem "$taskPpoisBuild/reports/*.docx").FullName
```

Экспортировать в свежий временный каталог: OmniNotation не перезаписывает существующие PNG, а добавляет числовой суффикс. `revise_reports.py` сохраняет титульники и несвязанные части документов, обновляет используемые рисунки, убирает только неиспользуемые отношения к изображениям и вложения. Повторная сборка проверена на эквивалентность XML содержимого, неизменность изображений и сохранение колонтитулов.

После экспорта PDF выполнить рендер через `Исходники/render_with_word.py` комплекта РОП и просмотреть все страницы. Только проверенные DOCX/PDF и используемые модели/иллюстрации заменяют канонические файлы. Проверка структуры или успешный экспорт сами по себе не заменяют содержательную и визуальную проверку.
