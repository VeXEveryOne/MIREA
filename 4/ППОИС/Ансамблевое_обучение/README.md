# Ансамблевое обучение — отдельная практика 7

Не путать с ППОИС 7 по проектированию БД. Методичка требует бэггинг и бустинг
на одном уникальном в группе датасете, сравнение качества и времени, отчёт
и Colab Notebook. Здесь выбран **Steel Plates Faults**: 1 941 строка,
27 признаков, семь классов. Уникальность в группе требует подтверждения;
отсутствие списка занятых наборов не является доказательством уникальности.

Источник: Buscema M., Terzi S., Tastle W. (2010),
[UCI Steel Plates Faults](https://doi.org/10.24432/C5J88N), лицензия CC BY 4.0.
Неизменённый исходный архив находится в `data/`; его SHA-256 проверяется при запуске.
Результаты, графики, CV и предсказания находятся в `outputs/`.

Актуальный отчёт: [DOCX](Ансамблевое_обучение_АлбахтинИВ.docx),
[PDF](Ансамблевое_обучение_АлбахтинИВ.pdf), 11 страниц. Он описывает именно
локальный CPU-запуск, а не предполагаемые результаты Google Colab.

`Ансамблевое_обучение_АлбахтинИВ.ipynb` самодостаточен для загрузки в Colab.
Вход в аккаунт и облачный запуск — отдельные действия; локальное исполнение
не называется выполнением в Colab. Среда фактического запуска записывается
в `outputs/results.json` и в outputs первой ячейки.

Для локальной проверки установить `requirements.txt` в отдельное окружение
и запустить `execute_notebook.py`. `build_notebook.py` пересоздаёт исходник
и сбрасывает outputs: после него обязательно выполнить notebook заново.

Контроль качества: единый stratified holdout 80/20, одинаковые CV-фолды,
подбор только на train, проверка отсутствия одинаковых признаков между train/test,
macro-F1 и ошибки каждого класса. Три замера fit/predict с чередованием порядка
и одним потоком. Тестовые 389 строк не участвуют в подборе параметров.

`verify_experiment.py` независимо переобучает модели, сверяет все 389
предсказаний каждого алгоритма, пересчитывает метрики, проверяет разбиение,
CV, структуру ансамблей, исходные замеры и исполненные ячейки. Результат
последней проверки — 45 успешных локальных проверок в `outputs/verification.json`.
В этом же файле отдельно записаны неподтверждённые условия Colab и уникальности.
Успешные локальные проверки не превращают их в выполненные требования.

Порядок повторного выполнения:

```powershell
# Команда python здесь обозначает отдельное окружение с requirements.txt.
python 4/ППОИС/Ансамблевое_обучение/execute_notebook.py
python 4/ППОИС/Ансамблевое_обучение/verify_experiment.py
# Сборка DOCX использует комплектный Python с python-docx, не ML-окружение.
python 4/ППОИС/Ансамблевое_обучение/build_report.py
```

`build_report.py` читает действительные results.json, CSV и verification.json;
он отказывается от сборки при несовпадении SHA-256 проверенных артефактов.
После создания DOCX требуется обновление полей, новый экспорт PDF, рендер
и просмотр всех страниц согласно общему README ППОИС.
