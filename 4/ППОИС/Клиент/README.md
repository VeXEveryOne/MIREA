# Локальный клиент ППОИС 10

Версия 0.2: просмотр каталога, редактор версий состава, серверный подбор и расчёт,
история ревизий карточки, создание новой расчётной ревизии DRAFT и диагностика.
HTML/CSS/JavaScript работают с локальным Python HTTP-сервером и PostgreSQL.
Роли, функции и маршруты заданы в `client_contract.json`.

## Запуск

Рабочий каталог — корень MIREA. В командах `python` означает отдельное окружение
с зависимостями [прототипа](../Прототип/requirements.txt), в текущем стенде
`.cache/ppois5-10/venv/Scripts/python.exe`. Нужен отдельный учебный PostgreSQL
на `127.0.0.1:55432` с локальной ролью `ppois_owner`, которая может создавать
учебные базы и роли. Не подключать рабочую БД или чужой кластер.

```powershell
python 4/ППОИС/Клиент/setup_client.py --output .cache/ppois5-10/client-environment.json
python 4/ППОИС/Клиент/server.py --environment .cache/ppois5-10/client-environment.json --port 8765
```

Открыть `http://127.0.0.1:8765`. Демонстрационные логины: `engineer`, `manager`,
`viewer`, `admin`; публичный учебный пароль — `coursework-demo`.
Не вводить пароли реальных сервисов. Сеанс действует 30 минут. Сервер слушает
только loopback; локальный HTTP и демонстрационная аутентификация не подходят
для промышленного размещения.

`setup_client.py` создаёт новую базу `ppois10_*` по неизменённой схеме №7,
загружает 48 учебных записей и сохраняет параметры только в `.cache/`.
Базы не удаляет и не сбрасывает. `--reuse` допускает только отдельную базу
с неизменёнными исходными 48 записями. Исходную БД доказательств №7 сервер
не принимает. Повторное выполнение setup без `--reuse` создаёт ещё одну базу,
поэтому не запускать его при каждом старте уже настроенного сервера.

## Проверки и модели

```powershell
python 4/ППОИС/Клиент/test_server.py
```

Этот прогон создаёт собственную отдельную БД и временный HTTP-сервер, проверяет
28 сценариев и пишет результат в `.cache/ppois5-10/client-api-verification.json`.
Он не воспроизводит пользовательские действия в браузере.

Сохранённая [сверка](Результаты_проверки.json) относится к зафиксированному
браузерному сценарию от 08.10.2026: 18 контрольных точек, 15 снимков и чтение
SQL после добавления версии и ревизии. Стало 56 записей: одна новая версия,
шесть позиций, одна ревизия; внешняя попытка публикации не добавлена.
Контрольные итоги: 53 500,00 руб., 76 400,00 руб., 7,820 кг.

`Исходники/verify_client_10.py` повторяет сверку только при наличии исходных
локальных журналов браузера, HTTP и настроек той же учебной БД в `.cache/`.
На новом компьютере эти наблюдения необходимо получить заново; одних
контрольных сумм недостаточно для доказательства нового исполнения.
Повторный HTTP-прогон также обновляет свой журнал: после него общую сверку
нужно повторить, прежде чем заново собирать отчёт.

`Исходники/verify_browser_10.mjs` воспроизводит 18 контрольных точек в Playwright
при уже запущенном локальном сервере на порту 8768. Сначала создать новую
учебную БД через `setup_client.py` и запустить сервер с её настройками:
сценарий добавляет одну версию и одну ревизию и требует исходных 48 записей.
Комплектный Node и Playwright берутся через `tools/runtime.mjs`. После запуска
выполнить `python 4/ППОИС/Исходники/verify_client_10.py`, чтобы сверить журналы,
снимки и фактические данные PostgreSQL перед сборкой отчёта.

`Исходники/build_client_models.mts` создаёт
`Схемы/ПР10_Клиент_функции_диалоги.omni`: дерево функций, четыре представления
ролей, три диалога и структурную схему. Для запуска используется комплектный
Node и установленный `tsx` OmniNotation согласно общему README ППОИС.

## Границы версии

Инженер добавляет новую версию, менеджер — ревизию DRAFT. История не
перезаписывается. Наблюдатель только читает и рассчитывает сохранённый состав;
администратор получает диагностику без автоматических бизнес-прав.

Подбор ограничен описанными доменными правилами, не перебирает все совместимые
комбинации. Предложения и время проверки — учебные, не текущие котировки.
Изображения доступны как метаданные, загрузки файла нет. Сохранённый ACCEPTED
с `demo-task-001` не доказывает публикацию в Ozon. Промышленный TLS,
аутентификация, аудит, нагрузка и восстановление не подтверждены.

Отчёт №10 в DOCX/PDF на 27 страниц подготовлен к сдаче. 08.10.2026 выполнен
новый рендер и просмотр всех страниц; пара документов прошла 2743 проверки
оформления и 67 содержательных сверок. Повторный HTTP-прогон прошёл все
28 тестов в отдельной новой базе. Новый браузерный запуск прошёл все 18
контрольных точек; наблюдения, 15 свежих снимков и SQL прошли 111 сверок.
Протоколы сохраняются в `.cache/`.
