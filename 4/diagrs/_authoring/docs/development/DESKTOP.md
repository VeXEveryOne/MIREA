# Настольное приложение Windows и macOS

Канонические ограничения — [AGENTS.md](../../AGENTS.md). Архитектура редактора описана в [каталоге модулей](../codebase/module-catalog.md), фактическая приёмка — в [отчёте рефакторинга](../status/EDITOR_REFACTOR.md).

## Команды и границы процессов

`domain/commands.ts` задаёт типизированные команды, подписи и сочетания клавиш. `main/menu.ts`, `App` и подсказки используют этот каталог. Основной модификатор — Command на macOS, Ctrl на Windows; выделение React Flow использует тот же выбор, Monaco — CtrlCmd. На Mac удаление доступно через Backspace и Delete. Undo/redo относятся к общему сеансу; в обычном текстовом поле меню направляет copy/paste/selectAll/undo/redo/delete в нативный ввод. Одиночные Backspace/Delete/F2 обрабатываются в renderer; меню не перехватывает их у поля ввода, но показывает сочетание из каталога.

`main/api.ts` и `preload.ts` предоставляют сведения о платформе, команды, уведомления открытия документов ОС и `rendererReady`. Node/fs остаются в main. Все запросы записи и восстановления проходят последовательную очередь IPC с проверкой отправителя. Создание окна выделено в `main/window.ts`, меню — в `main/menu.ts`, файлы — в `main/files.ts`, восстановление — в `main/recovery.ts`.

Экспорт PNG использует тот же доверенный IPC: renderer вычисляет tight-crop по DOM-границам узлов, связей и подписей общего `DiagramCanvas`, добавляет 32 px и передаёт целочисленный прямоугольник. Активный адаптер предлагает имя из показываемой диаграммы или листа; при пустом имени используется название вкладки. Main заменяет недопустимые символы в имени, снимает только известное расширение документа/PNG и сохраняет точки внутри названия, сверяет прямоугольник с content area текущего окна и просит Chromium заново отрисовать область через `Page.captureScreenshot` с масштабом до 4×. Размер ограничен 8192 px по стороне и 32 мегапикселями, после системного диалога PNG записывается атомарно. Произвольный путь или содержимое файла из renderer не принимаются.

## Окна и завершение

Адаптация 06.10.2026: стартовое окно не превышает 94% рабочей области основного
дисплея, сохраняя прежние верхние пределы 1540×980 DIP. Минимум высоты снижен
до 600 DIP и ограничен доступной областью вместе с минимумом ширины. Размеры
берутся в DIP, а UI-компактность — по фактическим CSS px окна, без webContents zoom
и изменения экспортной геометрии. Поэтому учитываются Full HD и масштабирование ОС.

На macOS закрытие окна сначала получает актуальный checkpoint от renderer; процесс остаётся в Dock. `activate` повторно создаёт окно, которое восстанавливает вкладки. Cmd+Q проходит `before-quit`, запрашивает checkpoint и завершает процесс только после очереди записи. На Windows последнее закрытое окно завершает приложение. Закрытие во время загрузки откладывается до `rendererReady`.

`open-file` регистрируется до `whenReady`; абсолютные пути `.omni` и старых совместимых расширений попадают в очередь. После восстановления renderer получает документы по одному. Аргументы второго экземпляра проходят тот же путь. Реализовано по [жизненному циклу Electron](https://www.electronjs.org/docs/latest/api/app); нативная приёмка на Mac ещё обязательна.

## Идентичность файлов и восстановление

Пути не приводятся к нижнему регистру. Существующие файлы сопоставляются через `stat` (device/inode), с `realpath` как резервным вариантом. Регистр расширения нормализуется только для выбора codec. Переименование не перезаписывает чужой файл: используется эксклюзивная hard-link операция с удалением старого имени; смена только регистра существующего имени допускается через rename, если каталог не содержит отдельную целевую запись. Файловая система без hard links возвращает понятную ошибку, исходник остаётся на месте.

Recovery хранит `workspace-v1.json` и отдельные снимки вкладок в `workspace-tabs-v1/`. Снимки с именем `<session>-<sha256>.json` записываются только при изменении содержимого; после них атомарно обновляется манифест, затем удаляются устаревшие снимки. Старые имена `<session>.json` читаются. Кеш проверки документов позволяет обновлять выделение/viewport без повторного декодирования модели. Открытый черновик и последняя корректная модель сохраняются вместе. Файловый отказ не разрешает закрытие окна молча.

Обновление 05.10.2026: build после генерации и проверки типов очищает только
генерируемый dist, затем собирает приложение и переносимый навык
omninotation-diagrams. Отдельная команда `npm run skill:build` пересобирает
его из канонических правил, реестра и примеров, сразу обновляя карту проекта.
Навык включает SKILL.md и соседний notation-instructions.md, без зависимости
от репозитория; README.txt с русской/английской инструкцией собирается в dist
и копируется рядом с EXE/.app и AI_Rules в корень пакета. Его нет в AI_Rules/asar.
Forge postPackage копирует dist/AI_Rules в корень папки сборки,
рядом с EXE или .app: оба Markdown-файла лежат прямо в AI_Rules. В extraResource и app.asar
навык не включается. Windows ZIP берёт всю папку; Squirrel включает AI_Rules
через явный additionalFiles (его штатный список не берёт произвольные папки).
На macOS postMake
добавляет AI_Rules и README.txt в ZIP рядом с .app, поскольку штатный ZIP maker берёт только
сам bundle. При переносе .app отдельно скопируйте AI_Rules отдельно.
Пользователь может скопировать папку в AI-среду с поддержкой навыков либо
прикрепить справочник к обычному чату. Рабочая папка docs и корневой README
не копируются в выпуск; примеры и лицензии остаются. Навык и лицензии
исключены из app.asar, чтобы не дублировать внешние файлы.
Очистка не затрагивает out, release-assets, документы, исходники или примеры.

| Команда | Среда | Результат |
| --- | --- | --- |
| `npm run package` | текущая ОС/архитектура | папка приложения |
| `npm run make:windows` | Windows x64 | Squirrel EXE и ZIP |
| `npm run make:mac:arm64` | macOS | arm64 `.app` и ZIP |
| `npm run make:mac:x64` | macOS | x64 `.app` и ZIP |

`npm run make` использует текущие платформу и архитектуру. ZIP и CI-артефакты различаются по платформе/архитектуре. Forge использует ICO для Windows, ICNS для macOS и регистрирует `.omni` вместе со старыми расширениями чтения в `CFBundleDocumentTypes`. Внутренние версии форматов от переименования расширения не меняются. Генерация отслеживаемых примеров — отдельная команда `npm run examples:generate`; build их не перезаписывает.

Имя продукта в Electron/Forge — `Omni Notation`: Windows-пакет содержит `Omni Notation.exe`, Squirrel создаёт `OmniNotation-Setup.exe`, macOS — `Omni Notation.app`. Техническое имя npm-пакета и CI-артефактов — `omni-notation`.

macOS-сборка выполняется на native runner: `macos-15` для arm64 и `macos-15-intel` для x64. Основание — [Forge build lifecycle](https://www.electronforge.io/core-concepts/build-lifecycle), [ZIP maker](https://www.electronforge.io/config/makers/zip) и [таблица GitHub runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners). Подпись, notarization и публикация не настроены в этой задаче. Подготовленная CI-конфигурация не является свидетельством успешной сборки или запуска на Mac.

После изменения lifecycle вручную проверяют закрытие/восстановление окна, Cmd+Q, Dock, open-file до готовности renderer, два разных регистра имён на case-sensitive томе и сохранение ошибочного черновика. Автоматизированные тесты запрещены действующими правилами проекта.
