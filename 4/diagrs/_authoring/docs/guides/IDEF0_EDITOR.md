# IDEF0 — функции и декомпозиция

IDEF0 показывает **что выполняет система, что преобразует, чем управляется и какими ресурсами работает**. Один файл хранит связанные листы. Основные действия — в [общем руководстве](USER_GUIDE.md).

## ICOM и листы

| Роль у функции | Сторона | Смысл | Пример |
| --- | --- | --- | --- |
| Input — вход | Слева | Что преобразуется | Заявка |
| Control — управление | Сверху | Правила/условия | Регламент проверки |
| Output — выход | Справа | Результат | Решение по заявке |
| Mechanism — механизм | Снизу | Ресурс/исполнитель | Оператор и ИС |

У связи двух функций роль описывает **получателя**: Output одной может стать Input/Control другой. Цвета: входы бордовые, управления синие, механизмы коричневые, выходы зелёные.

**A-0** — контекст с одной функцией №0. **A0** — её декомпозиция: для готового листа 3–6 функций; при построении можно начать с меньшего количества. Номер дальнейшего дочернего листа вычисляется по раскрываемому блоку.

## Пример: обработать заявку

1. Создайте IDEF0 → «Функциональная модель». Назовите функцию A-0 **«Обработать заявку»**.
2. В свойствах модели заполните цель **«Показать обработку от получения до решения»**, точку зрения **«Руководитель службы»**.
3. Соедините левую рамку с левой стороной функции: **«Заявка»**; верхнюю с верхней: **«Регламент проверки»**; нижнюю с нижней: **«Оператор и ИС»**; правую сторону функции с правой рамкой: **«Решение по заявке»**.
4. Выделите функцию и создайте декомпозицию. На A0 добавьте **1 «Принять заявку»**, **2 «Проверить заявку»**, **3 «Подготовить решение»**.
5. Соедините 1 → 2 **«Зарегистрированная заявка»**, 2 → 3 **«Результат проверки»**, обе роли получателя Input.
6. Внешний вход A0 подключите к 1, выход 3 — к внешнему выходу. Подключите управление/механизм; для общего потока используйте явное ветвление.
7. Нажмите **«Согласовать ICOM»**, проверьте сопоставления границ с родительскими стрелками. Проверьте готовность, сохраните.

A-0 отвечает, что делает система, A0 раскрывает ту же функцию с сохранением внешнего интерфейса. Шаблон «Лист декомпозиции» сразу даёт связанные A-0/A0 с тремя блоками. Готовый пример: `examples/cards-hierarchy.omni`.

## Стрелки и ветвление

Вся сторона функции/рамки доступна для подключения. Тяните рамка → функция или функция → рамка: внешний конец и стрелка создаются вместе. Для ручного создания выберите сторону/направление и добавьте **«Граничный интерфейс»**. Альтернатива — форма **«Соединить стрелкой»**: источник, получатель, роль, название.

Сторона рамки и направление независимы: in идёт снаружи внутрь, out — наружу. Порты функций сохраняют I/C/O/M. Для связанного конца разворот нужно согласовать со стрелками; сопоставленную дочернюю границу нельзя менять независимо от родителя.

У выбранной стрелки тяните круглые крепления и квадратные маркеры участков. Подпись двигается отдельно. Escape отменяет жест, отпускание — один шаг истории. Alt снимает обычную привязку маршрута. Автоматическая трассировка обходит функции, ручной маршрут можно уточнить.

ПКМ по стрелке → **«Сделать разветвление»** создаёт связанную ветвь. Ветви идут общим стволом, затем расходятся. Одинаковые названия независимых стрелок не создают развилку. Круглый маркер двигает точку ветвления. **«Выровнять потоки»** у функции разводит крепления, сохраняя противоположные концы.

## Декомпозиция, ICOM и туннели

Команда декомпозиции открывает существующий дочерний лист или создаёт новый. **«Корень»**, **«К родителю»** перемещают по иерархии. Title дочернего листа согласуется с именем родительской функции; Node — с её номером.

Дочерний интерфейс ссылается на конкретную родительскую стрелку, не на совпавшее название. **«Согласовать ICOM»** помогает восстановить сопоставления. Перед удалением родительского интерфейса проверьте использующие его границы.

Явные туннели: **локальная дочерняя граница** без интерфейса у родителя (`localOnly`) и **родительская стрелка, опущенная у ребёнка** (`omitChild`). Выберите режим в свойствах границы/стрелки. Сопоставление и туннель одного интерфейса одновременно недопустимы. Отсутствующая связь не становится туннелем автоматически.

**«Удалить декомпозицию»** удаляет дочерний лист/потомков, оставляя функцию. Удаление функции с декомпозицией затрагивает всё поддерево и требует подтверждения. Undo возвращает всё. Копирование переносит дочерние листы, ICOM и геометрию с новыми ID/номерами.

Старый отдельный A0 можно дополнить **«Добавить контекст A-0»**: контекст создаётся из границ, подробный лист сохраняется. Родитель отдельного A1 и глубже автоматически не угадывается.

## Размеры, подписи и штампы

Блок растягивается за нижний правый угол; точные размеры — в **«Размер и текст»**. Здесь же шрифт, перенос строк, у стрелки — ширина подписи. Shift+Enter добавляет строку, Enter завершает.

Рамка растягивается своим маркером либо через **«Граница диаграммы»** → **«Изменить размер листа»**. Минимум 720×520. При уменьшении блоки удерживаются внутри, при переносе за край лист расширяется. Стрелки на маркере меняют размер на 20 единиц, Shift — 100. **«Разложить»** перестраивает текущий лист и сбрасывает маршруты; **«Вписать»** меняет обзор.

Щёлкните ячейку штампа. Сверху USED AT, AUTHOR, DATE, PROJECT, REV, NOTE, статус, READER/DATE и автоматический CONTEXT; эти реквизиты общие для модели. Снизу Node, Title, Number конкретного листа. Number — свободный номер страницы, не номер функции. Статусы WORKING/DRAFT/RECOMMENDED/PUBLICATION выбираются щелчком. Пустые поля остаются пустыми, Escape отменяет ввод.

## Проверка и ограничения

Проверьте цель/точку зрения, управление/выходы функций, число блоков, связь родителя/ребёнка, ICOM и туннели. Незавершённость даёт замечания; неправильные ссылки, владельцы и циклы блокируются. Готовность не удостоверяет полный ISO-профиль.

Доступны связанные листы, ICOM, ветвление, непосредственные туннели, штампы, размеры/маршруты и общий PNG/PDF. Не реализованы join, Call Arrow, FEO и возобновление туннеля через несколько уровней. Сохранение выпускает IDEF0 v4; старые версии мигрируют, программа с поддержкой только v1–v3 новый файл не прочитает.
