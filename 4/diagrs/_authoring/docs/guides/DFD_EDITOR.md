# DFD — потоки данных

DFD отвечает на вопрос: **какие данные кто получает, преобразует и передаёт**. Реализован один уровень Gane–Sarson. Основные действия — в [общем руководстве](USER_GUIDE.md).

## Элементы

| Элемент | Смысл | Подпись |
| --- | --- | --- |
| Процесс | Преобразование входных данных в выходные | Проверить заказ |
| Внешняя сущность | Источник/получатель вне системы | Покупатель |
| Хранилище | Сохраняемые данные | Заказы |
| Поток данных | Что передаётся между объектами | Заявка, подтверждение |

Процесс называйте действием, поток — данными. «Нажать кнопку» описывает интерфейс, а «Заявка» — подходящий поток. DFD не показывает время, шлюзы или управляющую последовательность.

## Пример: принять заказ

1. Создайте DFD → «Диаграмма потоков данных».
2. Добавьте кнопками палитры внешнюю сущность **«Покупатель»**, процесс **«Проверить заказ»**, хранилище **«Заказы»**, процесс **«Подготовить подтверждение»**. Названия задайте через F2.
3. Расположите покупателя слева, проверку в центре, хранилище выше/ниже, подтверждение справа.
4. Протяните соединения из правой зоны источника в левую зону получателя по таблице. Назовите потоки двойным щелчком по подписи/линии или через свойства.
5. Обратный поток к покупателю разведите отдельно, чтобы не слить с заявкой.
6. Выполните «Проверить готовность» и сохраните.

| Источник | Получатель | Данные |
| --- | --- | --- |
| Покупатель | Проверить заказ | Заявка |
| Проверить заказ | Заказы | Проверенный заказ |
| Заказы | Подготовить подтверждение | Сохранённый заказ |
| Подготовить подтверждение | Покупатель | Подтверждение |

Готовая схема объясняет путь заявки, сохранение и возврат результата. Предметный пример «Заказы» доступен на домашнем экране/в проводнике.

## Маршруты и оформление

Выделенная стрелка показывает маркеры маршрута и креплений. Тяните квадратные маркеры участков, чтобы обойти фигуры; круглые маркеры меняют крепления. Подпись перемещается отдельно. Боковые зоны подключения широкие, попадать в маленькую точку не требуется.

В свойствах по мере появления ручной геометрии доступны **«Вернуть подпись к линии»**, **«Сбросить маршрут стрелки»**, **«Вернуть крепления к середине»**. Источник/получатель показаны для проверки; отдельного мастера переподключения DFD нет, сменить ссылки можно в тексте.

В меню `⋯` включается **«Привязка к сетке»**. Выровняйте выбранные блоки и впишите схему. Координаты в свойствах показывают положение; двигайте блок на полотне. Enter завершает подпись, Shift+Enter добавляет строку.

## Правила и ограничения

- У процесса должны быть осмысленные входы и выходы. Прямая передача между внешней сущностью и хранилищем нарушает профиль: нужен процесс, объясняющий преобразование.
- Не соединяйте две внешние сущности или два хранилища напрямую.
- Назовите потоки. Одинаковые подписи не объединяют независимые стрелки.
- Повторные ID и отсутствующие концы исправьте до продолжения. Часть нарушений правил DFD отображается диагностикой без блокировки рабочего сохранения.

Доступны одноуровневая модель, ручная геометрия, свойства, общие копирование/история, собственный текст, сохранение и PNG/PDF. Связанная декомпозиция DFD, балансировка уровней и выполнение процессов не реализованы.
