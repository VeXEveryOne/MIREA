# OmniNotation: руководство для AI-агентов

С 06.10.2026 интерфейс автоматически становится компактнее в небольшом окне
(до 1920 CSS px по ширине или 1050 по высоте, включая масштабирование ОС).
Размеры боковых панелей и кода адаптируются с коэффициентом 0.85; ручная настройка
разделителями сохраняется в базовом масштабе. Это оформление оболочки, не новый
параметр языка: масштаб полотна, модель и размеры экспортируемых фигур не меняются.

Оптимизация интерфейса от 05.10.2026 не меняет правила генерации схем и команды.
При свёрнутой на старте панели кода Monaco загружается только при первом
раскрытии. Поиск фильтрует списки отложенно; текущий текст сохраняется при
завершении редактирования. Предпросмотры разделителей объединяются по кадрам:
отпускание фиксирует последнее значение, Escape/потеря фокуса отменяет жест.
Черновики и checkpoint восстановления получают все события сессий, даже когда
оболочка не перерисовывается. Ручная приёмка этих оптимизаций ещё не заявлена.

Сборки от 05.10.2026 включают универсальный переносимый навык
`AI_Rules/` в корне сборки рядом с EXE или .app: SKILL.md и notation-instructions.md
лежат прямо в ней, без вложенных каталогов. Для среды с навыками скопируйте оба
Markdown-файла; README.txt в корне сборки рядом с AI_Rules содержит краткую
русскую и английскую памятку.
Поместите их в папку навыка omninotation-diagrams либо прикрепите
`AI_Rules/notation-instructions.md` к обычному чату. Это самодостаточный пакет
правил всех нотаций, не набор проектных навыков для разработки. Из исходников
он собирается командой `npm run skill:build`, также автоматически при build.

ERD, 05.10.2026: для концептуальной модели используйте `diagram type=conceptual`.
Это бинарный профиль Чена: entity/attribute/relation общие с logical/physical;
`entity weak=true` и `relation identifying=true` задают двойные контуры.
`attributeLink from=владелец to=атрибут` связывает овал; UI «Показать» добавляет такую
связь атомарно. Отдельный attribute view на logical/physical запрещён. Типы проверены;
полная ручная приёмка расширения ещё не заявлена. Подробности и ограничения —
[РОП](ROP_EDITORS.md#erd).

Для передачи инструкций другой нейросети используйте один файл [AI_NOTATION_INSTRUCTIONS.md](AI_NOTATION_INSTRUCTIONS.md): язык, все нотационные правила, текущий каталог типов/параметров и фактическое покрытие. Он пересобирается из документов и канонического реестра командой `npx tsx scripts/generate-notation-instructions.ts`. При каждом изменении проекта проверяйте актуальность правил построения согласно [AGENTS.md](../../AGENTS.md).

ERD CHECK: после удаления колонки её таблицы сохраняется `reviewRequired=true`. Проверьте выражение и только затем явно снимите отметку; до этого полный DDL не выдаётся. Автоматической текстовой подмены и исполнения CHECK нет.

FLOWCHART: у subroutine выберите `target`, затем «Открыть подпрограмму: …» для нужного листа вызываемого алгоритма. У offpage команда «Перейти к продолжению …» следует явной связи continuation; одинаковое имя не создаёт связь.

UML: «Переименовать ID…» в свойствах сущности → «Показать изменения ID» → предпросмотр → «Применить». Команда обновляет типизированные ссылки на всех листах, сохраняет геометрию и комментарии; выражения не заменяются. F2 по-прежнему меняет название.

Пакетный экспорт: в JSON-отчёте `items` перечислены все заказанные листы, их `completed/cancelled/error`, конкретные пути и ошибки. При отмене не считайте отсутствие файла успешным выводом; у частичного постера записанные части перечислены отдельно.

FUNCTION_TREE: визуальная смена parent/order и удаление функции с подъёмом детей требуют применения предпросмотра. Команда сохраняет ID детей и согласует root отдельных листов; неподходящие отображения снимаются с листа, сама ветвь остаётся в модели. Undo отменяет всю операцию.

ERD: двойной щелчок по строке — встроенная форма атрибута, Ctrl/Shift — набор строк для PK/UQ. CHART: axisLabel/unit в модели, цвет серии в layout.parts. Данные ошибочного draft сохраняются отдельно от принятого source; результаты проверок см. в ведомости РОП.

## С чего начать

1. Для подготовки диаграммы прочитайте [язык NS-TEXT-2](../reference/LANGUAGE.md) и строку нужной нотации ниже. Готовые документы находятся вне репозитория: [внешняя коллекция](EXTERNAL_DIAGRAMS.md). Точное текущее покрытие — [матрица поддержки](../status/SUPPORT_MATRIX.md).
2. Для изменения существующего файла сохраните его модель, принятый `source`, отдельный `draft` и `layout`. Сначала определите нотацию по содержимому JSON. Расширение `.omni` общее для всех моделей.
3. Для изменения приложения начните с [карты кода](../codebase/README.md), [каталога модулей](../codebase/module-catalog.md), подходящего проектного навыка и реального исходника. Сведения о поведении проверяйте по коду; планы и архивные отчёты не доказывают реализацию.

## Как пользоваться приложением

В IDEF0 название потока показывается только на стрелке, без дубликата и пустой плашки у рамки. Название `""` оставляет линию без подписи и без заглушки «Без названия». Чтобы задать имя, дважды щёлкните по линии стрелки. Автоматические внешние потоки получают ICOM-лестницу: C1/M1 — 28 единиц от рамки, далее шаг 20. Все автоматические потомки одного внешнего `rootArrowId` используют одну корневую развилку и общую полосу; общий ствол не создаётся простым совпадением роли или имени. Автомаршрут выбирает сначала длину, потом число углов; возвратный Input проходит ниже источника. Участки и концы примагничиваются каждые полтайла, Alt отключает магнит. Фиксированные тесные крепления/ручные пути допускают локальное сближение; перпендикулярные пересечения разрешены. Новые функции из кода получают зазор в пять клеток, лист расширяется при генерации, растяжении и перемещении за край. Выделенную функцию можно растянуть за нижний правый угол или задать ширину/высоту в «Размер и текст»; «Разложить» учитывает размеры. В этом же разделе доступны шрифт 8–72, автоперенос и ширина подписи стрелки. Shift+Enter в названии — явная новая строка, Enter — сохранить. Оформление — необязательный `layout.textStyles` IDEF0 v4; собственный язык не получает новых параметров.

Верхние реквизиты штампа IDEF0 общие для всех листов декомпозиции. Пустые поля не имеют заглушки, а CONTEXT автоматически показывает миниатюру родительского листа с выделенным блоком; на A-0 выводится TOP.

Выберите «Создать», нужную нотацию и шаблон либо откройте `.omni`. Добавляйте элементы из плавающей палитры над полотном; она остаётся доступной при свёрнутом проводнике. Выбирайте тип отношения перед соединением. Свойства выделенного элемента находятся справа, общий текст — в панели кода. UML имеет переключатель листов и команды «Лист модели» / «Показать существующий элемент».

Во всех нотациях кнопка создания показывает слева примерный символ элемента,
справа — название. Палитра UML разделена на раскрываемые группы «Фигуры»,
«Связи», «Свойства и события». Щелчок открывает форму создания; для фигур
Component/Activity/Deployment выбирает размещение на полотне, также доступно
перетаскивание. Свойства и события по-прежнему требуют своего владельца.
Миниатюры служат подсказкой и не добавляют новых типов или параметров языка.

Проверка готовности и привязка к сетке DFD доступны в меню «⋯» в верхней шапке. Общие команды вызываются через меню приложения и горячие клавиши; отдельная горизонтальная полоса команд удалена.

Общая шапка занимает 44 px, строка нотационных команд — 36 px. На узком окне
строка прокручивается горизонтально; переходы Tab между кнопками также открывают
скрытую часть. В IDEF0 переходы к корню/родителю, название текущего листа и
команды находятся в одном ряду. «Экспорт» открывает прежний выбор PNG/PDF.

Кнопки масштаба, вписывания и миникарты находятся справа снизу полотна, в одном
горизонтальном ряду. Миникарта изначально скрыта; кнопка «Показать миникарту»
включает её справа сверху, «Скрыть миникарту» отключает. Выбор запоминается по
нотации, не попадает в `.omni` и не меняет историю. Палитры имеют непрозрачный
фон без размытия. Эти настройки оболочки не меняют правила построения схем.

Вкладки открытых файлов расположены в верхней шапке между «Создать» и «Экспорт». Если вкладки не помещаются, прокручивайте их горизонтально. Перетаскивание меняет порядок, крестик или средняя кнопка мыши закрывает вкладку; двойной щелчок по имени позволяет переименовать файл.

Для новой схемы используйте «Создать» или Ctrl/Cmd+N; дополнительного «+» у вкладок нет. Тема переключается кнопкой с логотипом: тёмная оболочка использует графитовые поверхности и голубое выделение, включая редактор кода и списки выбора; полотно схемы и экспорт остаются светлыми.

Нижняя область состоит из кода слева (по умолчанию 70%) и ошибок/предупреждений справа (30%). Перетаскивайте вертикальную границу, чтобы изменить доли, и верхнюю границу области, чтобы изменить высоту. Двойной щелчок по вертикальной границе возвращает 70/30; она также управляется стрелками клавиатуры. Общая кнопка «↓» справа сворачивает код и ошибки вместе до строки заголовков; «↑» раскрывает всю область с прежней высотой и долями. Настройки запоминаются по нотации; щелчок по диагностике переводит к строке кода.

Кнопки «Применить код» и «Вернуть корректный код» появляются при наличии
неприменённого черновика. Сворачивание удаляет скрытый список диагностики из UI,
но сохраняет уже открытый Monaco и черновик; до первого раскрытия Monaco не
загружается, как и прежде.

| Удалить с полотна | Delete в Windows, Backspace в macOS; в UML это удаление отображения, не общей сущности |
| Найти | Ctrl/Cmd+F; диагностика открывает соответствующий элемент/строку, в UML — нужный лист |
| Получить картинку | «Снимок PNG» активного листа с Chromium-рендером до 4×; предлагаемое имя берётся из текущего листа/диаграммы (IDEF0: Node и Title); IDEF0 сохраняет весь лист от края до края, остальные нотации используют плотную обрезку; SVG/PDF-экспорта нет |

Ctrl/Cmd+A действует внутри редактируемого текста. Вне поля ввода он поглощается: выделения всего интерфейса или диаграммы нет. Статический текст оболочки не выделяется. Не советуйте старую комбинацию «Ctrl+A → Delete» для очистки полотна.

После изменения кода сеанс автоматически применяет кандидат через 400 мс; «Применить код» завершает ожидание. Ошибочный код остаётся в `draft`, а полотно показывает последнюю принятую модель. Исправьте код или выберите возврат к корректному исходнику перед визуальными правками. Ошибочный черновик можно сохранить. Предупреждение о незавершённости не равнозначно блокирующей ошибке: значим `blocksCommit`.

## Как писать диаграммы для OmniNotation

Используется собственный построчный NS-TEXT-2. Это не PlantUML, Mermaid, XML или исполняемый код. Полный синтаксис, допустимые поля, комментарии и экранирование описаны в [LANGUAGE.md](../reference/LANGUAGE.md).

```text
dfd orders "Обработка заказов"
entity customer Клиент
process accept "Принять заказ"
store archive Заказы
flow request Заказ from=customer to=accept
flow record "Данные заказа" from=accept to=archive
```

Порядок — `тип id название ключ=значение`. Поля разделяются пробелами, каждый элемент занимает строку. Многословные/специальные значения и пустая строка заключаются в двойные кавычки. ID стабильны, начинаются с латинской буквы или `_`; для переносимого примера используйте латиницу, цифры и `_`. Русские названия допустимы. Отступ не задаёт вложенность. Нотационные владельцы задаются предусмотренными ссылками (`in` в соответствующих нотациях, `owner` в UML).

UML-документ содержит и модель, и объявления листов/отображений:

```text
uml cards "Карточки товаров"
diagram classes "Классы анализа" type=class
datatype text Строка primitive=true
class card "Карточка товара" role=entity
attribute title Название owner=card classifier=text visibility=private
operation publish Опубликовать owner=card visibility=public
view cardView "" diagram=classes element=card
```

`card` — общая сущность, `classes` — лист, `cardView` — её отображение. Атрибут принадлежит классу, отображение — листу. Без view созданный элемент модели может не иметь собственной фигуры. Координаты находятся в `layout`, а не в строках языка. Новый лист ссылается на общую модель и может показывать те же элементы без копирования.

Правила, которые легко перепутать:

- `include from=base to=included`; `extend from=extension to=base`. Не разворачивайте стрелку по впечатлению от словесного сценария.
- Ассоциация классов имеет отдельные объявления `end`, а не только `from/to`; роль, кратность и навигация принадлежат концу.
- Сообщение ссылается на события `send/receive`, события — на участников и владельцев. Вертикальное перемещение не заменяет изменение порядка. Для `par` нет обязательной линейной очереди всех ветвей.
- В коммуникации `connector` ссылается на канал модели. Для его линии нужен view на том же листе и между теми же отображениями участников. Несколько сообщений могут использовать один канал.
- `reply` выбирается явно и связывается с исходным вызовом. Обратное направление не превращает обычный вызов в ответ.
- После изменения сложного взаимодействия проверьте выбор ветвей/шаги/повторения и выполните «Согласовать сценарий». Не подавляйте предупреждение простым обновлением fingerprint вручную.

Тип маленькой стрелки определяется `message.sort`:

| Значение | Отображение |
| --- | --- |
| `synchCall` | Сплошная, закрашенный треугольник |
| `asynchCall`, `asynchSignal` | Сплошная, открытый наконечник |
| `reply` | Пунктирная, открытый наконечник |
| `createMessage` | Пунктирная, открытый наконечник |
| `deleteMessage` | В текущем профиле сплошная с закрашенным наконечником; на последовательности — событие уничтожения получателя |

У UML допустим также закрашенный наконечник ответа; приложение использует открытый. Размер, интервалы и раскладка стрелок — решения редактора. Нормативное основание и отличия профиля — [UML_RULES.md](../UML_RULES.md).

## Как подготовить или изменить файл

`.omni` — JSON-контейнер, не просто текст с другим расширением. Он хранит `notation`, `formatVersion`, модель, принятый `source`, текущий `draft`, отдельный `layout`; у UML также есть профиль. Текущие версии: DFD 3, IDEF0 4, BPMN 3, UML 2; новые declaration-семейства — 1. Старые расширения `.nsdfd/.nsidef0/.nsbpmn/.nsuml` читаются для совместимости; неподдерживаемая внутренняя версия всё равно отклоняется.

В репозитории штатный путь работы с файлом — [`decodeProject(raw)` / `encodeProject(document)`](../../src/persistence/project.ts). Нотационные команды строят и проверяют целый кандидат; адаптер `applyText` принимает NS-TEXT-2 либо сохраняет только ошибочный draft. Для UML доступны [`createUmlDocument`, `applyUmlModel`, `updateElement`, `moveViews`, `setEdgeLayout`](../../src/notations/uml/document.ts); [`umlAdapter`](../../src/notations/uml/adapter.ts) связывает их с общим сеансом. Образец подготовки готового файла — [`generate-uml-example.ts`](../../scripts/generate-uml-example.ts).

При редактировании существующего файла не меняйте только `model` или только принятый `source`: декодер проверяет их согласованность. Сначала прочитайте файл штатным codec, затем примените нотационную команду/текстовый кандидат, проверьте диагностику и передайте результат в `encodeProject`. Сохраните комментарии, неизвестные текстовой проекции свойства, чужие листы и не относящуюся к правке геометрию. Ошибочный draft не заменяйте source без отдельного намерения пользователя.

Для UML отличайте удаление view от удаления модели с каскадом зависимостей. Копирование подграфа переназначает ID и собственные части; внешние ссылки внутри документа сохраняются, между документами переносятся зависимости. Не клонируйте JSON-строки простой заменой имён. Ручные подписи и изгибы каналов хранятся по view ID; маленькие стрелки коммуникации вычисляются заново из канала и выбранных сообщений. Смена раскладки не меняет причинность.

Приложение сохраняет файл атомарной заменой. Recovery хранится отдельно в userData, возвращает вкладки и черновики, но не записывает их поверх пользовательского файла без сохранения. Внешнее изменение/удаление исходного файла при восстановлении может потребовать «Сохранить как».

## Чего не обещать и как поддерживать справочник

В проекте нет публичного CLI/API для дистанционного управления запущенным редактором, выполнения UML/OCL или BPMN-процессов. Внутренние TypeScript-функции и npm-команды разработки не являются таким API. Приложение не формирует реальный BOM и не публикует карточки на маркетплейсе: эти действия моделируются в учебных примерах. Нет импорта сторонних языков, SVG-экспорта и полной сертификации перечисленных стандартов. PNG/PDF и пакетный экспорт описаны в [руководстве РОП](ROP_EDITORS.md).

Геометрия ищет свободное место, но не гарантирует отсутствие пересечений в произвольно плотном графе. Явно сохранённые положения подписей сохраняются; для нового размещения выберите «Автоположение подписи». Для изменения линии коммуникации откройте её канал; «Автомаршрут» снимает ручные bends. После изменения кода UI следует пересобрать, а фактическую приёмку проводить только в рамках разрешённого пользователем режима работы.

Разрешения на проверки и порядок работы задаются [AGENTS.md](../../AGENTS.md) и текущим запросом. Для расширений РОП выполнялись типы/сборки, отдельные ручные действия в браузере и вывод файлов штатным экспортом; результаты и непроверенные сценарии — в ведомости РОП. Автоматизированные тесты не запускались. Не создавайте временные сценарии исполнения в обход запрета на тесты.

После изменения поведения обновляйте соответствующую строку этого справочника, руководство/чеклист нотации и [журнал](../codebase/logic-changelog.md). [Генератор карты](../../scripts/generate-project-map.mjs) автоматически обновляет файловые хеши, импорты и команды; он **не переписывает смысловую документацию**. Её актуализирует разработчик/агент вместе с кодом. Порядок обновления карты после каждой правки закреплён в AGENTS.md.

## РОП: новые declaration-профили (27.09.2026)

ERD подключена к общей оболочке: логические и физические листы используют общие entity/attribute/key/foreignKey и отдельные view. Через палитру и свойства доступны таблицы, атрибуты, PK/UQ, мастер составного FK, CHECK, индексы, домены и последовательности. Удаление с полотна убирает view; удаление из модели показывает каскад. Кнопка DDL показывает PostgreSQL-текст перед сохранением .sql; приложение его не исполняет. Готовые диаграммы хранятся отдельно и не входят в сборку.

Все шесть семейств подключены к редактору и сохранению. UML v2 добавляет Component/Activity/Deployment и читает v1 с сохранением source/draft/layout. Подробные команды и примеры — [ROP_EDITORS.md](ROP_EDITORS.md); фактическая приёмка и остаток — [ведомость](../plans/ROP_IMPLEMENTATION.md).

В общем UI доступны «Проверить готовность», фильтры поиска по типу/листу, геометрия выделения, направляющие и явная сортировка текста. При проверке готовности предупреждения не блокируют сохранение. Примеры РОП открываются через создание новой схемы. Производственный пакетный экспорт: `npm run export:batch -- путь/manifest.json` после `npm run build`; существующие результаты не перезаписываются. В прототипе WIREFRAME общие команды изменения модели заблокированы до выхода из просмотра.

## ИМ: Гант, расширения UML, экспорт

GANTT зарегистрирован как собственный NS-TEXT-2 профиль и использует общий редактор. Доступны календарь/исключения, auto/manual, FS/SS/FF/SF, часы/ресурсы/нагрузки, резервы, baseline, пакетная вставка строк и WBS→план с preview. Физический PNG 300 dpi, интервальный и постраничный Гант — в общем экспорте. UML поддерживает локальный componentRealization, compact interface views, команды дорожек/ориентации/сворачивания и предварительную проверку смены связанных типов. См. [IM_EDITORS.md](IM_EDITORS.md).

11 примеров ИМ содержат 14 листов. Наличие функций/успешной сборки не означает завершённую приёмку: фактические действия и обязательные остатки перечислены в [ведомости ИМ](../plans/IM_NOTATIONS_IMPLEMENTATION.md). Не выдавать baseline за фактические данные, часы за длительность или критичность за ресурсный план.

В дополнениях ИМ доступны краткий/полный текст требований с настройкой печати, глубина вида дерева, drag задач Ганта и контекстное меню. Неподдержанные note/noteLink исключены из профиля GANTT; для аннотаций задач используется description. DEV-замеры операций выводятся локально как `[Omni timing]`; это наблюдение ручных действий, не автотесты.
