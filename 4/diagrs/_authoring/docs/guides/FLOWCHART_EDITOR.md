# Блок-схема — алгоритмы

Блок-схема показывает **порядок шагов, условия, циклы и вызовы алгоритмов**. Проект может содержать несколько алгоритмов и листов. Основные действия — в [общем руководстве](USER_GUIDE.md).

## Элементы

| Элемент | Назначение |
| --- | --- |
| Алгоритм | Владелец шагов; входы, выходы, предусловие, постусловие |
| Начало / конец | Границы выполнения |
| Операция | Действие; поле expression описывает вычисление |
| Ввод / вывод | Получение/выдача data |
| Решение | Условие expression; режим binary или multi |
| Подпрограмма | Вызов algorithm по устойчивой ссылке target; аргументы и результат |
| Соединитель / межлистовой соединитель | Обозначенная точка продолжения с code |
| Поток | Переход с guard либо признаком otherwise |
| Продолжение | Явная связь точек продолжения |
| Заметка / связь заметки | Пояснение |

Выберите фигуру в палитре, укажите место и заполните форму. Владелец шага должен быть нужным алгоритмом; расположение внутри нарисованной области не задаёт владельца.

## Пример: проверить сумму заказа

1. Создайте FLOWCHART. В свойствах алгоритма задайте вход **«Сумма заказа»**, выход **«Решение»**.
2. Добавьте **«Начало»**, ввод **«Получить сумму»**, решение **«Сумма больше нуля?»**, операции **«Принять заказ»**, **«Показать ошибку»**, конец **«Завершение»**.
3. У решения выберите binary, expression **«Сумма > 0»**.
4. Соедините начало → ввод → решение.
5. Используйте **«Две ветви решения»** в свойствах решения: выберите существующие операции. Для пути к принятию задайте guard **«Да»**, для ошибки — otherwise или согласованную отрицательную ветвь.
6. Соедините обе операции с концом. Подпишите результат, разложите схему и проверьте готовность.

Ожидаются два взаимоисключающих пути с достижимым завершением. Если ошибка должна возвращать пользователя к вводу, замените соответствующий выход на переход к вводу: циклы допустимы.

## Ветви и редактирование структуры

В binary оформите две ветви; в multi — несколько именованных условий и при необходимости иначе. Иначе задаётся признаком otherwise, а не только текстом «Иначе». Условия описывают выбор, но не вычисляются программой.

Команда вставки шага в поток делит переход на два; прежнее условие остаётся на первом участке. При смене типа шага/решения редактор показывает удаляемые поля и затронутые ветви. Просмотрите результат до применения.

Конец потока можно переподключить на полотне: предпросмотр перечисляет затронутые листы, изменение концов фиксируется вместе, ручной маршрут сбрасывается. Если на другом листе конец отсутствует/неоднозначен, сначала подготовьте его отображение.

## Подпрограммы и продолжения

1. Создайте второй алгоритм **«Рассчитать скидку»** и отдельный лист с его шагами.
2. На основном листе добавьте «Подпрограмма», выберите этот algorithm в target, задайте arguments **«Сумма»**, result **«Скидка»**.
3. В свойствах нажмите **«Открыть подпрограмму: …»**. При нескольких листах выбирается нужный; отсутствие листа показывается явно.

Ссылка идёт по ID алгоритма, переименование заголовка её не ломает. Вызов показывает структуру, не запускает вычисление.

Для длинного алгоритма создайте соединители/межлистовые соединители, задайте понятный code и явное continuation. Одинаковые подписи не заменяют отношение. Команда перехода к продолжению открывает соответствующую точку. Готовый малый пример: `examples/flowchart-continuation.omni`.

## Проверка и ограничения

Проверьте принадлежность шагов, достижимость от начала, завершение, полноту решений и ссылки вызовов/продолжений. Цикл допустим и не равен ошибке дерева; недостижимость и незавершённое решение диагностируются отдельно от неверного ID.

Доступны несколько алгоритмов, ручные маршруты, вставка шага, ветви, переходы, общая история, текст и PNG/PDF. Выражения, предусловия и постусловия хранятся как описание; исполнения алгоритма нет.
