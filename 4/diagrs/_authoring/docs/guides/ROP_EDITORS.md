# Редакторы комплекта РОП

Срез разработки 27.09.2026. Реализованы шесть новых семейств и три вида UML. Это локальные профили редактора, а не заявление полного покрытия стандартов. Ведомость требований и незавершённая ручная приёмка — [ROP_IMPLEMENTATION](../plans/ROP_IMPLEMENTATION.md).

## Документ и общий редактор

Новые семейства: ERD (`erd`), FLOWCHART (`flowchart`), FUNCTION_TREE (`functree`), SCHEME (`scheme`), WIREFRAME (`wireframe`), CHART (`chart`). Их контейнеры имеют formatVersion 1 и профиль `NS-<семейство>-1`. UML использует version 2 / `NS-UML-2.5.1-2`; v1 мигрирует без перестройки геометрии. DFD, IDEF0 и BPMN сохраняют прежние версии.

Один файл может содержать несколько `diagram`. Предметная сущность существует независимо от `view`. Кнопка «Показать на листе» использует существующее отображение; «Ещё одно отображение» создаёт второе явно. Delete убирает отображение, а «Удалить из модели» показывает каскад зависимостей. Геометрия, скрытые строки, цвета, изгибы и закрепление хранятся отдельно в layout. Наложение фигур не меняет owner.

Клик по палитре включает размещение, drag переносит новый элемент на полотно, Escape отменяет размещение. В свойствах доступны label, типизированные поля, отдельное переименование ID и зависимые части. Enter/blur фиксируют обычные поля. При ошибочном коде сохраняется draft и последняя принятая модель; семантические и layout-команды блокируются. Вернуться можно исправлением или явной кнопкой возврата принятого кода.

Monaco предлагает поля текущей декларации; новые декларации фильтруются по активному виду листа. Ссылки FK учитывают таблицу/ключ, ссылки компонентных концов — тип части, владельцы контролов — контейнеры без циклов. F12 ведёт к определению, Shift+F12 ищет типизированные ссылки. В меню «Текст…» доступны явное удаление хвостовых пробелов и сортировка по типу/ID между границами комментариев. Комментарии и следующая за ними декларация остаются на месте; значения order не меняются. Для узлов есть шаблон с `view` активного листа.

«Проверить готовность» применяет правила активного адаптера к принятой модели. Любое замечание или отдельный черновик означает «Требует завершения»; сохранить или экспортировать такую модель можно. Диалог экспорта перечисляет замечания до запуска. Готовность не изменяет строгость обычного редактирования.

«Геометрия…» выравнивает выделение по краям/центрам, распределяет интервалы и раскладывает в строку, столбец или сетку. Для UML есть явная раскладка сверху вниз/слева направо с учётом визуальных родителей; последовательности сохраняют порядок событий. Закреплённые узлы исключаются из раскладки. Во время перетаскивания видны направляющие, кнопка `#` переключает привязку к сетке. Повторный drag уже показанного элемента из проводника только выбирает его. Поиск включает описание и поля частей, фильтры ограничивают тип и лист.

FLOWCHART и SCHEME позволяют переподключить конец стрелки. До commit показываются затронутые листы; оба конца модели и отображений меняются одним действием, ручной маршрут сбрасывается. Если на другом затронутом листе конец отсутствует или неоднозначен, команда сообщает, какой лист нужно подготовить. Тип шага FLOWCHART меняется через просмотр удаляемых полей и проверку всех переходов.

Предметные примеры РОП доступны в окне создания для всех новых семейств и новых видов UML. Пакетный экспорт после сборки запускается командой `npm run export:batch -- путь/манифест.json`; оболочка сама запускает Electron с отдельным временным профилем.

Для новых семейств подпись связи перетаскивается отдельно. На выбранной связи двойной щелчок добавляет изгиб, маркер перемещает его, двойной щелчок по маркеру удаляет его. Escape отменяет жест. Такие действия изменяют layout одной операцией истории.

## ERD

Концептуальный лист `type=conceptual` использует бинарный профиль Чена: прямоугольник
сущности, овал атрибута и ромб связи; weak=true и identifying=true удваивают контур.
«Показать на листе» для атрибута показывает его владельца и создаёт/переиспользует
attributeLink одной операцией. Скрытие овала не удаляет колонку. Ключевые подчёркивания
производны от PK: у слабой сущности перенесённые части не маркируются как собственный
частичный ключ. Участие/кратность сохраняются в fromMin/fromMax/toMin/toMax.
Ручной label отношения задаёт предпочтительное положение ромба, проецируемое на линию;
ромб не отрывается от неё. Атрибутные линии без ручных изгибов прямые.
N-арные связи, составные/многозначные/производные атрибуты и специализация не добавлены.
Расширение не объявляется полным стандартом ER. Типы проходят проверку; ручная приёмка
редактирования, Undo/Redo и открытия расширенного файла пока не подтверждена.

Завершите изменение атрибута кнопкой «Применить атрибут» или Escape перед сохранением и переключением документа. Незавершённая встроенная форма удерживает операцию и показывает сообщение; Undo закрывает её без применения.

Двойной щелчок по строке открывает компактную форму имени/SQL-имени/домена/типа/nullable; Enter или «Применить атрибут» фиксирует её целиком, Escape отменяет. Расширенные параметры остаются справа. Пустая строка добавляет атрибут. Ctrl/Shift выделяет несколько строк для «Сделать PK/UQ»; мастер показывает порядок и снятие nullable перед применением. Если модель поменялась при открытой форме, откройте строку повторно.

Команда «Изменить FK и пары…» открывает родительский ключ, дочерние колонки и правила; перед применением показаны изменяемые декларации. Переподключение согласует модель и геометрию на всех листах. Та же атомарная операция доступна новым UML-связям. В выборе нового типа decision явно отмечаются удаляемые ветви; при вставке шага в поток условие сохраняется на первом участке.

Режим Drop включается явно: для схемы создаёт member, для каркаса меняет owner, для Activity назначает partitionMember, для артефакта создаёт deployment. До применения виден кандидат с изменениями текста. Отмена возвращает принятую модель и геометрию. Вложенные free/vertical/horizontal-области каркаса учитывают заголовок, padding, gap и закрепление.

Малые примеры: [порты и части](../../examples/component-ports.omni), [параллельность и pins](../../examples/activity-parallel-pins.omni), [повторное размещение](../../examples/deployment-repeated-artifact.omni), [межлистовой алгоритм](../../examples/flowchart-continuation.omni), [поддерево](../../examples/function-tree-subtree.omni), [сегменты BOM](../../examples/scheme-code-segments.omni), [таблица и modal](../../examples/wireframe-table-modal.omni), [ноль, missing и отрицательные числа](../../examples/chart-zero-missing.omni). Первые три доступны в окне создания UML. Генератор — `scripts/generate-profile-examples.ts`.

Логический и физический листы показывают одни entity/attribute. PK/UQ — отдельные key/keyPart, FK — foreignKey/fkPart с явными парами. Мастера ключей, FK, индекса и преобразования M:N фиксируют кандидат целиком. Перестановка строк меняет order; скрытие строки не удаляет атрибут. Физические ссылки и подписи остаются привязаны к ID колонок. В инспекторе доступны гарантии кратности, отличающие намерение логической модели от ограничений БД.

DDL preview создаёт PostgreSQL CREATE TABLE, ALTER TABLE с FK и индексы после таблиц, допускает циклические зависимости. Последовательности создаются до DEFAULT. `sequence`, `defaultSequence` и `index.predicate` сохраняют дополнительные объекты исходного SQL. CHECK/default/predicate остаются непрозрачным текстом и не исполняются. Неподдержанные типы и незавершённые ограничения препятствуют выдаче полного DDL; негенерируемые бизнес-правила перечисляются. Примеры: [BOM](../../examples/bom-erd.omni), [РОП](../../examples/rop-erd.omni).

Удаление колонки мышью или кодом помечает CHECK её таблицы `reviewRequired=true`, не изменяя выражений по совпадению слов. Отметка сохраняется в `.omni` и показывает предупреждение; DDL требует сначала проверить выражение и явно снять «Требует пересмотра» в свойствах CHECK.

## Алгоритмы, функции и общие схемы

FLOWCHART хранит алгоритм, шаги, потоки с guard/otherwise, подпрограммы и межлистовые продолжения. Есть вставка шага в поток, создание двух ветвей решения и переход к продолжению. Цикл разрешён; недостижимость и незавершённое решение диагностируются отдельно от неправильных ссылок. Пример: [три алгоритма](../../examples/rop-flowchart.omni).

У подпрограммы команды «Открыть подпрограмму: …» перечисляют листы вызываемого algorithm по `target`. Если лист ещё не создан, это отмечено в свойствах. Названия алгоритмов не используются как ссылки.

FUNCTION_TREE использует parent/order/code. Нумерация вычисляется из иерархии; перенос ветви не меняет ID/code. Команды поднимают уровень, переносят под предыдущего соседа, создают лист поддерева и сворачивают ветвь. При удалении можно сохранить детей, подняв их к прежнему родителю. Пример: [дерево функций](../../examples/rop-function-tree.omni).

Перенос ветви и подъём детей сначала показывают изменения исходника. Порядок соседей уплотняется; views, вышедшие за корень отдельного листа, убираются только с этого листа. При удалении корня листа поддерева его заменяет прежний родитель (либо единственный ребёнок при удалении общего корня); позиция корневого отображения переиспользуется. Все изменения отменяются одним Undo.

SCHEME различает block/container/port/link/member и codePattern/segment. Профили кодирования, инфраструктуры и доступа используют этот общий набор. Членство в зоне — семантическое member, совместное перемещение — layout.group. Сегменты кода имеют порядок, смысл и пример; размер/позиция выносной подписи не являются частью реального кода. Пример [BOM и схемы](../../examples/rop-scheme.omni) сохраняет разделитель `-` из DEFAULT `BOM-000153`.

## UML Component, Activity и Deployment

Новые виды работают в общем UML-документе вместе с прежними usecase/class/sequence/communication. Остальные семь видов не входят в реализацию РОП.

Команды создания элемента/листа, открытия свойств и переименования раскрывают свёрнутый инспектор. Обычное выделение сохраняет выбранную пользователем компоновку панелей.

В UML отдельная команда «Переименовать ID…» в свойствах показывает новый ID и точный предпросмотр затронутых ссылок. F2 меняет только название. Применение выполняется одним Undo-снимком; текст комментариев, guards и других выражений сохраняется.

Component различает component, part, port, interfaceUse, usage, dependency, realization и componentConnector с двумя componentEnd. Мастер connector выбирает assembly/delegation, части и порты; согласованность интерфейсов проверяется. Порты крепятся к границе и сохраняют side/offset при resize. Перенос part в другой owner выполняется явной командой.

Activity различает action, initial, activityFinal/flowFinal, decision/merge, fork/join, objectNode, inputPin/outputPin и controlFlow/objectFlow. PartitionMember задаёт ответственность независимо от владельца Activity. «Открыть Activity» у callBehavior переходит к целевой модели. Тела/guards/joinSpec не исполняются.

Deployment хранит node/device/executionEnvironment, artifact, deployment, manifestation и communicationPath. Одну сущность artifact можно разместить в нескольких узлах; размещение не дублирует её. Направления стрелочного представления: location → artifact и artifact → реализуемый элемент. deploymentSetting — локальные параметры, не команды развёртывания. Пример [структуры РОП](../../examples/rop-uml-structure.omni) явно отмечает проектные допущения JRE/PostgreSQL и общего пакета API/worker.

Два [Sequence-сценария](../../examples/rop-uml-sequences.omni) используют существующие occurrence/message/fragment/operand. В них сохранены исходные сообщения и добавлены alt/loop/guards по ПР8. Ответ проверки Ozon находится внутри polling loop и ссылается на вызов; при неизвестном исходе повторная отправка вслепую не моделируется.

## Каркасы и числовое сравнение

WIREFRAME хранит screen/widget/option/tableColumn/tableRow/tableCell/uiAction/binding. Таблица редактируется по ID колонок и строк, ширина хранится по ID колонки. Контейнеры поддерживают свободную, вертикальную и горизонтальную раскладку, padding/gap и закреплённые элементы. Скрытые элементы можно показать для редактирования. Tabs и скрытые modal по умолчанию показывают начальное состояние.

«Просмотр прототипа» выполняет только локальные переходы navigate/openModal/closeModal/toggle и временные значения. Выход сбрасывает их, «Принять демонстрационные значения» записывает их явно. Внешние URL/HTTP/JS не выполняются. Карта навигации использует те же screen/uiAction. Пример: [шесть экранов](../../examples/rop-wireframe.omni).

CHART поддерживает bar/column, категории, серии, значения и missing. Пустая клетка означает отсутствие значения, ноль остаётся числом, отрицательные значения видны относительно нулевой линии. Явный диапазон не может обрезать данные. Округление применяется только к подписи; sourceNote содержит происхождение данных. Пример [сравнения](../../examples/rop-chart.omni): 2.1 / 3.7 / 3.7 / 3.1 / 5.0; последняя оценка — целевое покрытие проектируемой ИС, не результат измерения.

У CHART поле «Подпись числовой оси» (`axisLabel`) дополняет единицу; цвет выбранной серии хранится в layout по её ID и не меняет source или числа.

## Экспорт

Диалог «Экспорт PNG / PDF» выбирает активный лист, область выделения, список, весь проект или открытые проекты. Настройки: белый/прозрачный PNG, масштаб/ширина, поля, заголовок/подпись, шрифт, чёрно-белый вывод, A4/A3/свой формат, вписывание либо постер с перекрытием. Предпросмотр показывает первую страницу и предупреждает о мелком тексте. Неподдерживаемый шрифт заменяется Arial с предупреждением.

Экспорт создаёт отдельный скрытый экземпляр существующего NotationEditor/DiagramCanvas с собственной копией сеанса. Принятая модель выводится целиком, в том числе за краем рабочего viewport; рабочее выделение, pan/zoom и история не меняются. UI и точки редактирования исключаются. PDF печатается средствами Chromium из HTML и SVG, без XML-сериализации. Полностью векторный результат для всех CSS-эффектов не гарантируется.

Файлы записываются с числовым суффиксом при конфликте имён. Отчёт JSON перечисляет файлы и ошибки, а `items` — каждый заказанный лист с порядком, нотацией, diagram ID и результатом `completed`, `cancelled` либо `error`. При частичном выводе постера сохраняется перечень уже записанных частей. Отмена останавливает дальнейшие файлы после текущей операции; подготовка предпросмотра тоже отменяется. Пакетный CLI использует ту же реализацию: `electron dist/export-cli.cjs manifest.json` после сборки `config/vite.export.config.ts`. Манифест содержит `output`, необязательные `options` и `jobs` с `file`, `diagramId`, `title`; пути разрешаются относительно манифеста. Это вывод моделей, не дистанционное управление работающим приложением.

## Перенос РОП

Перемещение выбранных фигур клавишами-стрелками (20 единиц, Shift — 100) фиксирует layout в общей истории. Из проводника можно перетащить существующую сущность на лист: добавляется view; владелец модели сохраняется. Допустимость отображения проверяет адаптер.

Дублирование переносит собственные части с новыми ID, оформление, ручные маршруты и ссылки на части. При копировании в другой документ сначала показывается перечень новых деклараций, включая необходимые зависимости. Для скопированного plot/screen/вызванного algorithm сохраняются отдельные листы. Начальный экран проекта остаётся прежним. Undo отменяет весь перенос одной операцией.

В ERD перед сменой SQL-типа показаны связанные FK. Типы соседних колонок не меняются; несовместимое изменение отклоняется целиком. В прототипе disabled/loading контейнера блокирует вложенные контролы. Параметр экспорта скрытых элементов показывает также скрытые панели и модальные окна.

Генераторы `scripts/migrate-rop-*.ts` читают исходники без изменения, создают собственные модели и отчёты происхождения, не исполняют SQL и формулы. `scripts/rop/build-register.ts` связывает 38 номеров с конкретными файлами/листами и создаёт манифесты PNG/PDF. Повторный перенос создаёт новую версию результата, а реестр выбирает последний отчёт. Ручная приёмка не выводится из успешного decode/build; её результаты фиксируются отдельно.
