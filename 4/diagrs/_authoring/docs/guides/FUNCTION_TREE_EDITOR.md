# Иерархии — функции, оргструктура, WBS, FURPS+

Все четыре профиля используют дерево: **у каждого узла один основной родитель**, порядок соседей и дополнительные связи. Выберите профиль при создании; его поля и допустимые виды узлов различаются. Основные действия — в [общем руководстве](USER_GUIDE.md).

## Профили и примеры

| Профиль | Узлы | Что получить |
| --- | --- | --- |
| tree | Функции | Разложение возможностей системы |
| org | Организация, подразделение, роль, сотрудник | Подчинение и ответственность |
| wbs | Проект, сводный этап, пакет работ | Состав результата и трудоёмкость |
| furps | Корень, категория, подкатегория, требование | Систематизированные требования FURPS+ |

### Дерево функций

1. Создайте пустое дерево функций. Добавьте корень **«Обработка заказов»**.
2. Добавьте **«Принимать заказ»**, **«Проверять наличие»**, **«Выдавать результат»**, выбрав корень в parent и порядок 0, 1, 2.
3. У «Принимать заказ» создайте детей **«Вводить данные»**, **«Проверять заполнение»**.
4. Выполните раскладку, откройте структурный список и проверьте подчинение.

Основные линии вычисляются из parent, вручную соединять их обычной стрелкой не нужно.

### Оргструктура

1. Создайте org: организация **«Служба заявок»** → подразделение **«Операторы»** → роль **«Оператор»** → сотрудник с известным именем.
2. У подразделения/роли заполните функции и headcount; у сотрудника — fullName и manager, где поля доступны.
3. При необходимости добавьте functional/project crossLink для функционального или проектного взаимодействия.

Количество штатных ролей и реально заведённые сотрудники — разные сведения. Не заполняйте ФИО догадкой из названия должности.

### WBS

1. Создайте wbs: проект **«Запуск приёма заявок»**, сводный этап **«Подготовка»**, пакеты **«Описать процесс»**, **«Создать форму»**, **«Проверить запуск»**.
2. У пакетов задайте deliverable, acceptance, ownerRole, устойчивый externalCode и effortHours, например 8, 16, 8.
3. Проверьте итог 32 часа. Неизвестные часы оставьте пустыми — это не ноль.
4. Нажмите **«Создать отдельный план Ганта»**, если нужны сроки. В новом документе отдельно задайте длительности и зависимости по [руководству Ганта](GANTT_EDITOR.md).

Часы хранятся у пакетов, суммируются по дереву один раз. Свёрнутая/скрытая ветвь продолжает участвовать в итоге. Вычисляемый номер меняется при перестановке, externalCode и ID сохраняются.

### FURPS+

1. Создайте furps, корень **«Требования к приёму заявок»**, категорию **F — Функциональность**.
2. Добавьте требование с устойчивым кодом **F-01**, текстом **«Оператор может сохранить заявку»**, priority must, status draft.
3. Заполните source и verification **«Проверить сохранение и повторное открытие заявки»**.
4. После согласования установите agreed. Только после фактической проверки установите verified и подтвердите актуальный текст.

Категории: F — функциональность, U — удобство, R — надёжность, P — производительность, S — сопровождаемость, X — дополнительные ограничения. Приоритеты must/should/could, статусы draft/agreed/verified. Наличие критерия само по себе не подтверждает выполнение.

## Переносить и упорядочивать ветви

Поле parent меняет основного родителя, order — положение среди соседей. Команды повышения уровня и **«Опустить под предыдущую»** выполняют перенос с предварительным просмотром. Циклы и недопустимые родители отклоняются. Выровненные номера вычисляются из иерархии; numbering auto/none управляет их показом, не устойчивым code.

**«Открыть поддерево»** создаёт/открывает лист существующей ветви. **«Свернуть / развернуть»**, направление сверху вниз/слева направо и **«Глубина вида»** меняют отображение, не parent. **«Структурный список»** показывает ту же модель.

При удалении из модели можно поднять детей к прежнему родителю вместо удаления всей ветви; просмотр показывает изменения. Удаление отображения оставляет узел. Раскладка сохраняет закреплённые фигуры; конфликт отменяет операцию с объяснением.

## Дополнительные связи и ссылки

CrossLink не меняет подчинение и суммы. Допустимые виды: org — functional/project; wbs — related; furps — refines/depends/related. Они отображаются пунктиром с видом связи. Для обычного дерева доступные дополнительные связи выбираются по его профилю.

Reference прикрепляет к узлу документ/externalID и вид requirement/idef0/other. Это ссылка происхождения, не автоматическое создание внешней модели. Используйте её, чтобы объяснить источник функции/требования.

## Устойчивость требований и связь WBS с Гантом

**«Перенумеровать коды…»** в FURPS+ показывает изменения до принятия. Повторный код блокируется, неверный префикс категории предупреждается. При verified сохраняется снимок проверенного текста. Изменение текста предлагает вернуть draft; устаревший снимок диагностируется. Команда подтверждения актуального текста требует основания проверки, а не только смены статуса.

Созданный из WBS план имеет sourceDocumentId/sourceNodeId. В Ганте **«Импорт / обновление WBS…»** сопоставляет устойчивые ID и показывает изменения. Исчезнувшие пакеты не удаляются молча, часы назначений не переписываются автоматически. Зависимости и сроки не выводятся из часов.

## Проверка и ограничения

Проверьте единственный корень/принадлежность, родительские циклы, допустимые виды узлов, уникальность кодов, неизвестные часы, основание verified. Схема описывает организацию/работы/требования; она не подтверждает штат, выполнение проекта или приёмку системы.

Готовые примеры: `examples/im/im-org.omni`, `im-wbs.omni`, `im-furps.omni`; пример отдельной ветви — `examples/function-tree-subtree.omni`.
