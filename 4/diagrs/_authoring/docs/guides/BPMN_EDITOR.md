# BPMN — бизнес-процесс

BPMN показывает **ход процесса, участников, выбор пути и реакцию на события**. Здесь описан реализованный профиль собственного редактора. Основные действия — в [общем руководстве](USER_GUIDE.md).

## Элементы

| Группа | Доступные элементы | Назначение |
| --- | --- | --- |
| Действия | Обычная, пользовательская, ручная, сервисная, скриптовая задача; бизнес-правило; отправка/получение; вызов | Работа в процессе |
| Составные действия | Подпроцесс, транзакция, ad-hoc подпроцесс | Группа внутренних работ |
| События | Начало, конец, промежуточное получение/отправка, граничное | Причина начала, результат, реакция |
| Шлюзы | Исключающий, параллельный, включающий, комплексный, событийный | Выбор/согласование путей |
| Участники | Пул, дорожка | Участник и ответственность внутри него |
| Данные/пояснения | Объект данных, хранилище, аннотация, группа | Информация отдельно от управления |
| Связи | Последовательность, сообщение, ассоциация | Порядок, межучастниковый обмен, пояснение |

Палитра «Элементы схемы» имеет поиск и группы. Перетащите элемент или нажмите кнопку добавления. Для вложения отпустите его внутри пула, дорожки или раскрытого подпроцесса; граничное событие — на действии. Первый пул охватывает существующий процесс, дорожки размещаются внутри своего пула.

## Пример: проверка заявки

1. Создайте BPMN → «Бизнес-процесс». Добавьте пул **«Обработка заявок»**, дорожки **«Оператор»** и **«Сервис»**.
2. На дорожке оператора разместите начальное событие **«Заявка получена»** и пользовательскую задачу **«Проверить заявку»**. Проверьте «Контейнер» и «Дорожка» в свойствах.
3. После проверки добавьте исключающий шлюз **«Данные корректны?»**.
4. Добавьте сервисную задачу **«Зарегистрировать заявку»**, отправку **«Сообщить об отказе»** и конечные события **«Заявка принята»**, **«Отказ отправлен»**.
5. Соедините начало → проверка → шлюз; шлюз → регистрация → успешный конец; шлюз → отказ → конец отказа.
6. У потока к регистрации задайте условие **«Данные корректны»**. У шлюза выберите поток отказа как **«Поток по умолчанию»**.
7. Назовите потоки, впишите схему, проверьте готовность и сохраните.

После проверки выбран ровно один путь. Параллельный шлюз здесь запускает обе ветви и не заменяет проверку «да/нет».

## Связи и участники

Редактор определяет доступный тип связи по концам и контексту; обязательного переключателя вида над полотном нет. У действий вход слева, выход справа; у шлюзов есть вертикальные точки. Данные имеют свои точки подключения.

**Последовательность** соединяет шаги одного процесса. **Сообщение** соединяет разных участников: добавьте второй пул «Покупатель» для межучастникового обмена. Дорожки одного пула не становятся разными участниками. **Ассоциация** связывает пояснение/данные и не запускает следующий шаг. Её направление выбирается в свойствах: None, One, Both.

## События

В свойствах выберите **«Определение события»**: Message, Timer, Conditional, Signal, Error, Escalation, Cancel, Compensate, Link, Terminate. Допустимость зависит от вида события и места в процессе. Не каждый пункт списка допустим для любого события; исправляйте сочетание по диагностике.

| Параметр | Как использовать |
| --- | --- |
| Timer | Длительность, дата или цикл; `PT5M` — пять минут. Не задавайте несколько альтернатив одновременно |
| Conditional | Запишите условие события |
| Link | Дайте согласованное имя паре промежуточных Link-событий одного процесса |
| «Прерывающее» | Для start событийного подпроцесса и boundary задаёт прерывание, если выбранный контекст допускает |

Boundary прикрепляется к действию, а не располагается рядом для вида. Error, Cancel, Compensation имеют специальные ограничения. Несколько восстановленных определений события сохраняются; менять их набор через эту форму пока нельзя.

## Повторения, шлюзы и контейнеры

У действия **«Повторение»**: none, standard, parallel, sequential. Для многоэкземплярного выполнения задайте число экземпляров/выражение. Флаг компенсации описывает компенсирующее действие и не заменяет петлю.

У подходящего действия и exclusive/inclusive/complex шлюза выбирается исходящий поток по умолчанию. У последовательности задаётся условие. **«Направление шлюза»**: Unspecified, Converging, Diverging, Mixed. Событийный шлюз имеет Exclusive/Parallel и флаг создания экземпляра; после него выбирайте допустимые ожидающие события/задачи.

У подпроцесса доступны раскрытие и **«Событийный подпроцесс»**. Поле контейнера меняет принадлежность, не только позицию. **«Закрытый пул»** показывает участника без процесса. У данных есть **«Коллекция данных»**, у объектов — «Документация».

Завершите форму **«Применить свойства»**; Escape отменяет ввод. Изменения проверяются целиком. Преобразование с потерей скрытых свойств отклоняется.

## Проверка и ограничения

Проверьте начало/завершение путей, владельцев, условия/default, сообщения между пулами и крепление boundary. Незавершённость допускает сохранение; неправильные ссылки/комбинации блокируются.

Приложение не выполняет процесс, таймеры, выражения и компенсации. Палитра не означает полного покрытия BPMN 2.0. Используются собственный текст и JSON `.omni`; BPMN XML не импортируется и не экспортируется.
