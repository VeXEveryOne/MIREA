# Общая схема — блоки, зоны и связи

Общая схема подходит для **инфраструктуры, доступа, произвольных связей и структуры идентификатора**. Она не навязывает правила DFD/BPMN. Основные действия — в [общем руководстве](USER_GUIDE.md).

## Профили и элементы

Профили general, infrastructure, access, coding выбираются у листа. Общие элементы: блок, зона, надпись, связь, включение в зону, заметка/связь заметки. Структура кода и сегменты доступны в coding/general.

| Настройка | Варианты/назначение |
| --- | --- |
| Форма блока | rectangle, rounded, ellipse, diamond, cylinder, document, cloud |
| Роль | client, gateway, application, database, storage, external; principal, authentication, authorization, operation, deny, audit; generic |
| Детали блока | technology, version, resources, policy |
| Зона | public, dmz, internal, generic |
| Связь | association без направления, directed, bidirectional |
| Детали связи | protocol, port 1…65535, purpose |

Форма и роль независимы: цилиндр может изображать БД, но смысл задаётся role. Подписи/поля описывают проект; программа не устанавливает сервер и не проверяет реальную сеть.

## Пример: путь заявки до базы

1. Создайте infrastructure или общую схему. Добавьте зоны **«Внешняя сеть»** (public), **«DMZ»** (dmz), **«Внутренняя сеть»** (internal).
2. Создайте блоки **«Браузер»** role client, **«Шлюз»** gateway, **«API заявок»** application, **«База»** database с формой cylinder.
3. Создайте «Включение в зону»: браузер во внешней зоне, шлюз в DMZ, API/база во внутренней. Либо включите режим Drop, перетащите блок в зону и просмотрите создаваемое членство.
4. Создайте directed связи браузер → шлюз → API → база. Для первых двух задайте HTTPS/443, для последней — проектный протокол/порт выбранной БД.
5. Запишите technology/version только по известным сведениям, resources — по проектным требованиям. Разведите линии, проверьте и сохраните.

Результат показывает зоны доверия и назначение каналов. Нарисованная зона без member не задаёт принадлежность автоматически.

## Схема доступа

В профиле access разместите principal → authentication → authorization → operation. От authorization добавьте ветвь к deny, от действий — к audit. В policy запишите правило, например **«Редактирование разрешено роли Оператор»**; на связях — результат разрешения/отказа.

Ромб визуально удобен для решения, но общая схема не вычисляет условия и не превращается в исполняемую политику доступа. Если нужен алгоритм с проверкой полноты ветвей, используйте [блок-схему](FLOWCHART_EDITOR.md).

## Структура кода: BOM-000153

1. Создайте coding, добавьте «Структура кода» с именем **«Код изделия»**.
2. Добавьте к ней segment order 0, kind literal, literal **BOM**.
3. Добавьте order 1, literal **-**.
4. Добавьте order 2, kind counter, width 6, alphabet digits, example **000153**, meaning **«Порядковый номер изделия»**.
5. Проверьте показ **BOM-000153** и пояснения сегментов.

Типы segment: literal — фиксированная часть, counter — счётчик, value — значение. Для переменной части задайте width, alphabet digits/latin/any, example и meaning. Порядок задаётся order. Разделитель является отдельной частью кода, не декоративной линией. Размер/положение выносного пояснения не меняет значение сегмента. Пример: `examples/scheme-code-segments.omni`.

## Зоны, маршруты и свойства

Member связывает owner-зону с блоком/вложенной зоной; циклы недопустимы. Геометрическая группа отличается от членства: она лишь перемещает отображения вместе.

Выбирайте вид связи в строке команд либо при создании. Подпись и изгибы перемещаются отдельно. Переподключение конца показывает затронутые листы и сбрасывает ручной маршрут; подготовьте отображения обоих концов на каждом затронутом листе.

Надпись text служит свободному пояснению. Заметка может быть связана с объектом noteLink. Оформление, закрепление, отдельные листы, копирование и PNG/PDF используют общие команды.

## Проверка и ограничения

Проверьте владельцев зон, отсутствие циклов, концы связей, диапазон порта и порядок/пример сегментов. На рисунке отличайте факты от проектных предложений. Нотация не рассчитывает совместимость технологий, ёмкость сервера, сетевую достижимость или реальные права.
