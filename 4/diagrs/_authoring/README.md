# OmniNotation

DFD, BPMN, IDEF0 и четыре вида UML используют общий сеанс, историю, команды и автоматическую синхронизацию кода. [Подготовка macOS](docs/development/DESKTOP.md) · [Фактическая приёмка](docs/status/EDITOR_REFACTOR.md) · [Руководство для AI-агентов](docs/guides/AI_AGENT_GUIDE.md).

[![CI](https://github.com/Korgerk/OmniNotation/actions/workflows/ci.yml/badge.svg?branch=codex%2Fsimple-syntax-bpmn)](https://github.com/Korgerk/OmniNotation/actions/workflows/ci.yml)

Версия 0.1.0 готовится как **черновик**, не опубликованный стабильный выпуск. [Изменения](CHANGELOG.md) · [GitHub Actions](https://github.com/Korgerk/OmniNotation/actions) · [Порядок выпуска](docs/CI_RELEASES.md).

Локальный редактор диаграмм для Windows: визуальная схема и собственный текстовый язык в одном документе. Название приложения в сборке — **Omni Notation**, текущая версия — 0.1.0.

![Редактор DFD](docs/screenshots/dfd.png)

Скриншот из ранней DFD-версии иллюстрирует интерфейс; показанный на нём синтаксис может отличаться от текущего.

## Что доступно

| Нотация | Статус |
| --- | --- |
| DFD, Gane–Sarson | Один уровень; графика ↔ текст, свойства, история, поиск, копирование, сохранение и восстановление |
| BPMN 2.0 | Начальный профиль: палитра, свойства, применение кода, собственная модель и история; покрытие неполное |
| IDEF0 | Связанные листы A-0/A0/A1…: декомпозиция, дерево/DRE, ICOM по ID, явные туннели, ветвление стрелок (fork), рамка и штампы каждого листа, история, контейнер IDEF0 v4 и миграция v1/v2/v3. Join и Call пока нет. Цель — ISO/IEC/IEEE 31320-1:2012, не полная сертификация |
| UML | Четыре редактора: варианты использования, классы анализа, последовательности и коммуникация; UML v1 в `.omni`, пять связанных примеров. Остальные десять видов WIP; [покрытие и ограничения](docs/status/UML_CHECKLIST.md) |

Доступен снимок активного листа в PNG. Декомпозиция DFD, полный BPMN и экспорт SVG/PDF ещё не реализованы. Точное покрытие — [матрица поддержки](docs/status/SUPPORT_MATRIX.md) и [чеклист BPMN](docs/status/BPMN_CHECKLIST.md).

## Общий язык

BPMN использует собственный визуальный редактор на React Flow с собственными SVG-фигурами и командами; bpmn-js удалён. [Возможности и ограничения](docs/development/NATIVE_BPMN_EDITOR.md).

Каждое объявление: `тип id название ключ=значение`, одно на строку. Параметры необязательны и разделяются пробелами. Многословные/специальные значения — в кавычках. Без `\`, запятых, скобок и `;`.

```text
dfd orders "Обработка заказов"
entity customer Клиент
process accept "Принять заказ"
store archive Заказы
flow request Заказ from=customer to=accept
flow record "Данные заказа" from=accept to=archive
```

В BPMN вариант задачи задаётся параметром: `process checkOrder "Проверить заказ" type=user`. Код автоматически применяется через 400 мс после ввода; кнопка «Применить код» применяет его сразу. При ошибке черновик сохраняется рядом с последней принятой моделью. Все нотации сохраняются в собственном JSON-контейнере `.omni`; поле `notation` и версия внутреннего формата определяют модель. Старые `.nsdfd`, `.nsbpmn` и `.nsidef0` открываются для совместимости. XML запрещён правилами проекта.

[Синтаксис](docs/reference/LANGUAGE.md) · [Руководство пользователя](docs/guides/USER_GUIDE.md) · [DFD-пример](examples/orders.omni) · [BPMN-пример](examples/process.omni)

IDEF0: **Создать → Функциональная модель** открывает редактируемый контекст A-0. Добавьте границы и соедините их с точками функции или используйте форму «Соединить стрелкой». Сохранение — Ctrl+S, на macOS — Cmd+S. [Краткое руководство](docs/guides/IDEF0_EDITOR.md) · [Контекст-пример](examples/cards-context.omni) · [Лист декомпозиции](examples/cards-decomposition.omni).

## Запуск из исходников

Нужны Git, Node.js 24 и npm. Из текущей папки проекта:

```powershell
npm ci
npm start
```

`npm start` собирает проект и запускает Electron. `npm run dev` запускает только Vite; это не полный desktop-сеанс с файловым IPC.

| Команда | Назначение |
| --- | --- |
| `npm run generate` | Перегенерировать Langium AST |
| `npm run typecheck` | Статическая проверка TypeScript |
| `npm run build` | Грамматика, типы, чистый dist, renderer/main/preload/export, лицензии и универсальный AI-навык |
| `npm run skill:build` | Только переносимый AI-навык из текущих правил, реестра и примеров |
| `npm run clean:build` | Удалить только генерируемый dist текущего проекта |
| `npm run package` | Пакет Electron Forge для текущей платформы |
| `npm run make:windows` | Windows x64: Squirrel и ZIP |
| `npm run make:mac:arm64` / `make:mac:x64` | На macOS: `.app` и ZIP нужной архитектуры |
| `npm run examples:generate` | Отдельная генерация отслеживаемых примеров |
| `npm run map` | Обновить карту проекта без установки зависимостей |

После упаковки приложение находится в `out/Omni Notation-win32-x64/Omni Notation.exe` и требует всю соседнюю папку; установщик — `out/make/squirrel.windows/x64/OmniNotation-Setup.exe`. Эти артефакты создаются локально и не входят в исходный checkout.

Полный [указатель документации](docs/README.md). Конфигурации сборки находятся в `config/`. Автоматизированные тесты и их команды удалены; до явного обратного указания пользователя их нельзя создавать или запускать.

## Универсальный навык для нейросетей

Каждый build создаёт прямо в `dist/AI_Rules/` два Markdown-файла: `SKILL.md` и
`notation-instructions.md`, без вложенных папок. Навык общий для всех зарегистрированных
нотаций. В корне сборки рядом с приложением и папкой `AI_Rules` лежит `README.txt`
с краткими инструкциями на русском и английском.
Правила, каталог и примеры берутся из текущих источников.
Forge кладёт папку `AI_Rules` в корень сборки рядом с `Omni Notation.exe`
на Windows или `Omni Notation.app` на macOS. Она видна сразу после распаковки ZIP;
на Windows входит и в установку Squirrel. Отдельный ZIP навыка не нужен.

Для среды с навыками скопируйте оба файла в папку навыка `omninotation-diagrams`.
Для обычного чата достаточно прикрепить
`AI_Rules/notation-instructions.md`, назвать нотацию и описать нужную схему.
Навык не зависит от репозитория или конкретного провайдера нейросети.
Поддержка установки навыков зависит от выбранной AI-среды.

Перед сборкой удаляется только генерируемый `dist`, чтобы не оставались старые
хешированные файлы. `out`, исходники и рабочая документация автоматически не удаляются.
В пакет не включаются архивы, планы, карты кода и скриншоты из `docs`, а навык и
лицензии не дублируются внутри app.asar. Примеры `.omni` и лицензии сохраняются.

## Состояние проверок и лицензии

Иконка EXE: положите свою `icon.ico` в `config/assets/` и выполните `npm run make`. Она используется для приложения, окна и установщика. [Подробности и требования к файлу](config/assets/README.md).

Автоматизированные тесты запрещены действующими правилами. Фактические типы, сборки, ручная браузерная приёмка и непроверенные нативные сценарии — в [отчёте рефакторинга](docs/status/EDITOR_REFACTOR.md). Архив прежних результатов не подтверждает текущую версию.

Стек: Electron, React, TypeScript, React Flow, Monaco, Langium, bpmn-moddle (дескрипторы BPMN), Zod, Vite и Forge. Версии зафиксированы в package-lock.json, атрибуция библиотек сохраняется. Собственная лицензия проекта отдельным LICENSE пока не определена.
