1. Назначение практической работы

Цель работы — освоить полный базовый цикл анализа табличных данных:
подготовить воспроизводимое Python-окружение, загрузить данные, проверить их
структуру и качество, выполнить предобработку, получить описательные
статистики, сформировать простые аналитические срезы, визуализировать
закономерности и сохранить подготовленный набор данных в обменных и
аналитических форматах.
В отличие от работы, построенной вокруг отдельных конструкций языка Python,
здесь синтаксис используется только как инструмент решения аналитической
задачи. Каждая операция должна сопровождаться интерпретацией результата.
Студент отвечает не только на вопрос «что вернула функция?», но и на вопрос
«что это означает для исследуемого набора данных?».
Ожидаемые результаты обучения

• проводить базовый EDA: распределения, частоты, групповые статистики,
  корреляции и поиск потенциальных выбросов;
• выбирать базовый тип визуализации под аналитический вопрос;
• экспортировать подготовленные данные и формулировать воспроизводимые

3. Минимальное введение в Python, NumPy и Pandas для анализа

Python хранит значения в объектах с динамическими типами, однако для анализа
данных критично не столько объявление переменных, сколько структура массива
и тип элементов. NumPy предоставляет однородные многомерные массивы
ndarray и векторные операции, а Pandas — Series и DataFrame с индексами,
именованными столбцами и смешанными типами данных.
Главный практический принцип — по возможности заменять построчные циклы
векторными выражениями. Операция над целым столбцом читается как
аналитическое правило и обычно эффективнее Python-цикла.
Практический блок 3.1. Векторное преобразование
В следующем фрагменте будет смоделирован типичный для анализа данных
переход от исходной единицы измерения к производной. Три значения скорости
ветра в м/с объединяются в массив, затем весь массив одним выражением
переводится в км/ч по формуле v_km/h = 3.6·v_m/s. Функция np.round(array, 2)
округляет все элементы результата до двух знаков после десятичной точки.

 import numpy as np

 wind_ms = np.array([1.14, 0.80, 0.97])
 wind_kmh = wind_ms * 3.6
 print(np.round(wind_kmh, 2))

Результат выполнения
 [4.10 2.88 3.49]

Умножение выполняется сразу для всего массива. Точно тот же принцип
используется ниже для столбца DataFrame: df["wind_speed_ms"] * 3.6.

4. Форматы файлового хранения данных и загрузка CSV

CSV — текстовый табличный формат без строгой схемы типов: значения
хранятся строками, а типы восстанавливаются при чтении. JSON удобен для
вложенных и полуструктурированных объектов, но при записи табличных
данных часто занимает больше места. Parquet — бинарный колоночный формат,
сохраняющий типы и ориентированный на аналитическое чтение отдельных
столбцов. В последующих работах Spark будет особенно эффективно
использовать Parquet.

Практический блок 5.2. Пропуски, дубликаты и уникальные значения
Следующий код выполняет три независимые проверки качества данных: полноту,
наличие полных дублей и кардинальность признаков. Сначала будет подсчитано
число пропусков по каждому полю, затем — число полностью совпадающих
строк, после чего для всех столбцов определяется количество уникальных

значений. Кардинальность особенно важна для распознавания категориальных
признаков и для обнаружения полей, которые внешне имеют числовой dtype, но
фактически являются кодами категорий.
Метод isna() строит DataFrame логических значений: True соответствует
пропуску, False — заполненному элементу.
Последующий sum() суммирует True как единицы и тем самым даёт число
пропусков по каждому столбцу.
duplicated() возвращает булеву маску полных повторов строк; её sum() считает
количество таких повторов.
Метод nunique() вычисляет число различных значений отдельно для каждого
столбца.

 print("Пропуски по столбцам:")
 print(df.isna().sum())
 print("Полных дубликатов:", df.duplicated().sum())
 print("Число уникальных значений:")

Практический блок 5.3. Проверка соответствия кода и категории
Задача этого блока — проверить семантическую согласованность двух
представлений одного и того же признака числового type_id и текстового
type_name. Из исходной таблицы будут выделены только эти поля,
повторяющиеся пары удалены, а уникальные соответствия отсортированы по
коду. Если одному коду соответствовало бы несколько названий или одному

6. Типы данных и предобработка

Предобработка — это не обязательное исправление каждого столбца, а

данных. Категории целесообразно хранить как category, небольшие
целочисленные коды — в компактных целых типах, числовые преобразования
выполнять векторно. Удалять строки следует только при наличии обоснованной
причины.
В данном файле пропусков и полных дубликатов нет, поэтому очистка не должна
искусственно удалять наблюдения. Вместо этого полезно оптимизировать dtypes

8. Корреляция и потенциальные выбросы

Коэффициент корреляции Пирсона оценивает линейную связь двух числовых
признаков и лежит в диапазоне от −1 до 1. Значение около нуля означает
отсутствие выраженной линейной связи, но не отсутствие любой зависимости.
Корреляция также не устанавливает причинность.
Для первичного поиска необычных значений можно использовать
межквартильный размах IQR = Q3 − Q1. Эвристическое правило помечает
значения за пределами [Q1 − 1,5·IQR; Q3 + 1,5·IQR]. Такие наблюдения являются
кандидатами на дополнительную проверку, а не автоматически ошибками.

Практический блок 8.2. Правило IQR на примере скорости ветра
Следующий фрагмент не удаляет данные, а только маркирует необычные
значения скорости ветра по стандартному правилу 1,5·IQR. Сначала вычисляются
квартильные характеристики и границы, затем строится булева маска всех
наблюдений, лежащих вне интервала. В конце выводятся сами параметры правила
и число кандидатов.
Метод quantile(p) возвращает квантиль заданного уровня. Квантиль уровня p=0.25
соответствует первому квартилю Q1, p=0.75 — третьему квартилю Q3.
Межквартильный размах вычисляется как iqr = q3 - q1, после чего формируются
эвристические границы Q1 - 1.5·IQR и Q3 + 1.5·IQR.
Два сравнения с границами объединяются оператором | — поэлементным
логическим «ИЛИ». Полученная маска содержит True для кандидатов на выброс,
а mask.sum() считает их число.

 q1 = df["wind_speed_ms"].quantile(0.25)
 q3 = df["wind_speed_ms"].quantile(0.75)
 iqr = q3 - q1
 lower = q1 - 1.5 * iqr
 upper = q3 + 1.5 * iqr

 mask = (
     (df["wind_speed_ms"] < lower) |
     (df["wind_speed_ms"] > upper)
 )

 print(f"Q1={q1:.3f}; Q3={q3:.3f}; IQR={iqr:.3f}")
 print(f"Границы: [{lower:.3f}; {upper:.3f}]")
 print("Кандидатов:", mask.sum())

Результат выполнения
 Q1=0.110; Q3=0.660; IQR=0.550
 Границы: [-0.715; 1.485]
 Кандидатов: 3652 (13.69% строк)

10. Экспорт CSV, JSON и Parquet

После анализа следует сохранить не сохраненное notebook-состояние, а явно
сформированный итоговый экспортированный во внешний файл набор данных в
виде DataFrame. CSV удобен для обмена, JSON — для полуструктурированного
взаимодействия, Parquet — для последующей аналитической обработки. Для
корректного сравнения форматов необходимо записывать одну и ту же таблицу и
фиксировать параметры кодировки и сжатия.
Практический блок 10.1. Сохранение подготовленного DataFrame
Один и тот же подготовленный clean_df будет сохранён в трёх форматах в
отдельный каталог output. Это принципиально важно для корректного сравнения:
различаться должен формат хранения, а не содержимое таблицы. После
выполнения блока появятся CSV для совместимого обмена, JSON Lines для
построчного полуструктурированного представления и Parquet для
аналитического чтения с сохранением схемы и колоночной организацией.
Объект Path("output") задаёт каталог результатов, а OUT.mkdir(exist_ok=True)
создаёт его, не выдавая ошибку, если каталог уже существует. Оператор / у
объектов Path формирует путь к файлу.
Метод to_csv() записывает таблицу в CSV; index=False исключает технический
индекс, encoding="utf-8" задаёт кодировку.
Метод to_json() с orient="records" и lines=True формирует JSON Lines — один
объект на строку; force_ascii=False сохраняет не-ASCII символы.
Метод to_parquet() использует движок pyarrow и сжатие snappy для записи
колоночного Parquet.

 OUT = Path("output")
 OUT.mkdir(exist_ok=True)

 clean_df.to_csv(
     OUT / "FiresRu_clean.csv",
     index=False,
     encoding="utf-8"
 )

 clean_df.to_json(
     OUT / "FiresRu_clean.json",
     orient="records",
     lines=True,
     force_ascii=False
 )

 Формат нельзя оценивать только по расширению. Для учебного отчёта

 повторного чтения и возможность выборочного чтения столбцов. Parquet
 особенно важен как мост к следующему блоку курса — распределённой

Практический блок 10.2. Проверка round-trip
После экспорта данные будут прочитаны в два новых объекта csv_back и
parquet_back. Сначала сравниваются размеры таблиц, затем исследуются типы,
восстановленные из Parquet. Эта проверка нужна, чтобы убедиться, что файлы
действительно пригодны для продолжения аналитического pipeline, а не просто
были созданы на диске. Особое внимание следует уделить различию между
текстовым CSV, где схема восстанавливается при чтении, и Parquet, где она
хранится вместе с данными.
Термин round-trip означает цикл <записать данные, прочитать их обратно,
проверить результат>.

Функция pd.read_csv() повторно загружает CSV и заново выводит типы из
текстовых значений, тогда как pd.read_parquet() читает сохранённую Parquet-
схему. Атрибут shape позволяет сопоставить число строк и столбцов с исходным
DataFrame, а dtypes показывает тип каждого столбца в повторно загруженной

После повторного чтения необходимо убедиться, что число строк и столбцов
совпадает с сохранённым DataFrame. Для CSV часть типов может быть
восстановлена заново, тогда как Parquet хранит схему и обычно лучше сохраняет
аналитические dtypes.
