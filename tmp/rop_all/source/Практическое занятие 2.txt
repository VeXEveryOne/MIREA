Использовать инструменты (Draw.io, PlantUML, ArchiMate, текстовый и табличный редактор) для визуализации моделей и оформления таблиц. Теоретический вспомогательный материал Function Tree (дерево функций) — это иерархическая модель, которая используется для описания функциональной структуры системы. В её основе лежит принцип разбиения общей цели на подфункции и конкретные задачи. На верхнем уровне располагается основная функция системы (например, «Управление заказами»). Далее происходит декомпозиция: каждая функция разделяется на подфункции, которые уточняют её содержание. Для каждой функции указываются: • входы (данные, запускающие выполнение функции); • выходы (результаты выполнения); • ответственные исполнители. Дерево функций позволяет: • определить, какие задачи должна решать система;

Она показывает состав системы, её программные модули и то, как они взаимодействуют между собой. Основные элементы диаграммы компонентов: 1. Компоненты — отдельные части системы (модули, сервисы, базы данных, интерфейсы). 2. Интерфейсы — точки взаимодействия между компонентами. 3. Связи (dependencies) — линии, которые показывают, какой компонент использует другой. Диаграмма компонентов позволяет: 1. Формализовать архитектуру системы. 2. Определить границы и функции каждого модуля. 3. Понять, как отдельные части приложения взаимодействуют между собой. Пример фрагмента представлен ниже на Рисунке 1.

Use Case (сценарий использования) — это описание того, как пользователь (или внешняя система) взаимодействует с проектируемым приложением для достижения определённой цели. Сценарии помогают понять требования к системе и определить, какие функции должны быть реализованы. Основные элементы Use Case: 1. Акторы (Actors) — пользователи или внешние системы, которые инициируют взаимодействие. 2. Предусловия — условия, которые должны выполняться перед началом сценария. 3. Основные действия — последовательность шагов, выполняемых актором и системой. 4. Результат — итог выполнения сценария (что получает пользователь или система). Использование сценариев позволяет: 1. Формализовать требования к системе. 2. Уточнить функционал интерфейса и бизнес-логики. 3. Согласовать ожидания пользователей и разработчиков. Пример описания сценария в Таблице 2.2.
