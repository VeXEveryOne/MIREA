Использовать инструменты (ERwin, Draw.io, SQL Designer, текстовый и табличный редактор) для построения модели и оформления таблиц. Теоретический вспомогательный материал ERD (Entity–Relationship Diagram, диаграмма «сущность-связь») — это модель, которая используется для проектирования структуры базы данных. Она описывает объекты предметной области (сущности), их характеристики (атрибуты) и то, как они связаны между собой (отношения). Основные элементы ERD: 1. Сущность (Entity) — это объект, информация о котором хранится в системе (например: Клиент, Заказ, Товар). 2. Атрибуты (Attributes) — характеристики сущности (например: у Клиента есть ФИО, телефон, email). 3. Первичный ключ (Primary Key, PK) — уникальный идентификатор записи в таблице (например, ID клиента). 4. Связи (Relationships) — определяют, как сущности связаны друг с другом (например: Клиент оформляет Заказ). Типы связей:

1. 1:1 (один к одному) — каждой записи в первой сущности соответствует ровно одна запись во второй. 2. 1:N (один ко многим) — одной записи первой сущности может соответствовать несколько записей второй (например: один клиент может сделать много заказов). 3. M:N (многие ко многим) — нескольким записям одной сущности соответствуют несколько записей другой (например: заказы содержат товары, и товары входят в разные заказы). Использование ERD позволяет: 1. Спроектировать структуру базы данных. 2. Определить ключи и связи между таблицами. 3. Обеспечить целостность и непротиворечивость данных. Схема описывает: 1. Структуру кода (из каких частей он состоит). 2. Правила присвоения (что означает каждая часть кода). 3. Диапазоны значений (например, коды регионов от 01 до 99). Пример схемы кодирования, код клиента имеет вид:  CL-YYYY-NNNN • CL — префикс, обозначающий сущность «Клиент»; • YYYY — год регистрации; • NNNN — порядковый номер клиента за год. Таким образом, код CL-2025-0153 означает: «Клиент, зарегистрированный в 2025 году, № 153 по порядку». Схема кодирования помогает: • избежать дублирования кодов; • сразу по коду получать часть информации (например, дату создания); • унифицировать данные при интеграции с другими системами.
