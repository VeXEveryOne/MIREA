# Инструменты репозитория

Запускать команды из корня MIREA. Для инвентаризации достаточно Python 3.12 или новее; при сборке отчётов нужны зависимости соответствующей работы.

```powershell
python tools/repository_audit.py --hash --output .cache/repository_audit.json
```

Проверка показывает объём каталогов, точные SHA-256 дубликаты, временные файлы, вложенные Git-репозитории и битые локальные ссылки Markdown. Она ничего не удаляет и не входит в подмодули. Повторяющиеся исходники независимых заданий, Gradle Wrapper и отдельные копии данных для самостоятельных практик могут иметь одинаковые хэши и сохраняются по назначению.

`quarantine_files.ps1` применяет явный JSON-план очистки: проверяет все пути и хэши до первого перемещения, затем переносит выбранные файлы в резервную папку вне репозитория. Без `-Apply` выполняется только проверка. Файл `moved_files.json` в резервной папке содержит исходные и новые пути.

`runtime.mjs` находит установленные библиотеки Node, инструменты документов и исходники OmniNotation; `runtime.py` предоставляет те же настройки путей инструментам Python. Настройки при переносе на другой компьютер:

- `OMNINOTATION_ROOT` — каталог репозитория OmniNotation; локальное значение по умолчанию `D:/OmniNotation`.
- `CODEX_RUNTIME_ROOT` — каталог `dependencies` комплектной среды Codex.
- `CODEX_SKILLS_ROOT` — каталог установленного пакета `openai-primary-runtime`.

Сборка РОП описана в [Исходники/README.md](../4/РОП/Практики_1-8/Исходники/README.md). Генератор KNIME и его исходные изображения находятся в [каталоге презентации](../4/BD/KNIME/README.md).

`report_formatting/bd/` содержит форматирование черновых DOCX по единому справочнику, экспорт через Word и инструменты проверки. Стадии форматирования и результаты проверки создаются в `.cache/bd-format/`. Перед применением к готовым отчётам соблюдать правила визуальной проверки из справочника.
